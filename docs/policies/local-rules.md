# Local rules — aoe2

Repo-scoped directions that outlive the task that produced them. Fleet-wide rules live in `../fleet/FLEET.md`; this file is only for things true of *this* repo.

Each line names a rule and links its file, which holds the rule in full, why it exists and its evidence; open that file when the work reaches the rule. Entries refer to one another by title, and "above" and "below" mean earlier and later in this list.

- [Lessons: the index returns as a queue, and every entry names its gate (2026-09-02, owner)](rules/lessons-queue.md).
- [What "done" means for this project (2026-09-03/04, owner, standing)](rules/done.md): The game is built **to completion**, matching Age of Empires II: Definitive Edition. The acceptance test is a sentence, and it is re-checked every time the work looks finished: **"can we play this and feel like we're playing DE?"**
- [Worktrees are the default, and only `scripts/controlWorktree.mjs` makes or removes one (2026-09-22; replaces "A/B control builds: never `ln -s` node_modules into a worktree", 2026-09-05)](rules/worktrees.md): Nobody runs `git worktree remove`, `rm -rf`, `Remove-Item -Recurse` or `rmdir /s` on a worktree by hand, and nobody puts `node_modules` into one any other way. **Workers are never spawned with the harness's built-in worktree isolation** (the Agent tool's `isolation: "worktree"`; owner, 2026-09-22).
- [The HUD is inside the Definitive Edition target (2026-09-25, owner), and there is one HUD (the coordinator's reading); replaces "HUD styling: modern, not medieval" (2026-08-18)](rules/hud-de-target.md): Authoritative description: `design/spec-final.md` §14.1 "HUD chrome".
- [The HUD holds its shape, and nothing floats over the minimap (2026-09-02, owner)](rules/hud-shape.md): Entering a mode — placement, a menu, a queue filling up — must not move, shrink, or hide the controls the player was just using (a label may make room for the mode's own pill; a button may not move), and no floating element (tooltip, toast, badge) may cover the minimap.
- [Rendering is inspected from several angles and zoom levels (2026-08-23, owner)](rules/rendering-angles.md): Whenever the rendering changes, look at the result from **multiple camera angles and multiple zoom levels** before calling it done — not one framing, and not only the region that was edited.
- [Every feature is playtested the way a human plays (2026-08-23, owner)](rules/playtest-like-a-human.md): A feature is not done when its tests pass — it is done when a full match has been played with it. Bringing back a scheduled or CI LLM playtest, or adding a provider secret for one, is the owner's call.
- [Behaviour matches the real Age of Empires II (2026-08-23, owner)](rules/behaviour-matches-de.md): The game must **function identically to the real Age of Empires II** — same costs, rates, counters, tech-tree gating, controls, and consequences.
- [A map-generation change is measured against the maps it cannot reach (2026-09-04)](rules/map-generation-controls.md): Any change to map generation is A/B'd on the whole seed set, and the maps the change CANNOT touch are the control: they must come back **byte-identical on every column of both owners**.
- [Standing-loop entry point (2026-09-02, owner)](rules/standing-loop.md): The canon rule "a standing loop takes its next task from exercising the artifact the way its user does" resolves here to **playing a real match**: `npm run dev`, scenario `aoe2-prototype` (fog on, a real base), default zoom, the human slot — then sweep the whole frame for what is WRONG before choosing what to work on.
- [Several sessions, one repo: one writer per checkout (2026-09-03, owner)](rules/several-sessions.md): The rule that makes that safe is not a habit, it is a boundary: **a checkout has exactly ONE writing session at a time.**
  - **Take a lane.** One session owns the shared checkout at `github/aoe2` and does the integrating — merges, version bumps, changelog, gates, pushes.
  - **In a shared checkout, never use a whole-tree command.** Stage by explicit pathspec (`git commit -m ... -- path/one path/two`).
  - **No `git stash` at all while a peer is live.**
  - **Never run destructive git in a checkout you do not own** — `reset`, `checkout --`, `merge --abort`, `clean`.
  - **One preview port per session, never the default.**
  - **One full suite at a time, machine-wide (2026-09-25).** Take the lock with `mkdir C:\Users\38909\Documents\github\aoe2\tmp\gate.lock`, which fails while another holder has it: wait and retry.
  - **A session that lands code holds the lock from its final rebase through its push (2026-10-10; announced to peer sessions 2026-09-25).** A docs-only push needs no lock and may go while one is held.
  - **`dist/` is per checkout, not per session.**
  - **Pull before push; never force-push `main`.**
  - **A generated file changing under you is not a conflict to resolve.**
  - **Untracked files you did not create are someone's work in progress.** Leave them.
- [A feature's cost is its own share of tick time, never whole-match ticks per second (2026-09-05)](rules/feature-cost.md): Whole-match ticks per second over an A/B is not a cost measurement and must not be written up as one.
- [A thread is closed by the task that closes it, and every task ends with a look at the open ones (2026-09-05, owner)](rules/threads.md): At the end of every task, each thread in `current/` that the task advanced gets a dated status line saying what moved and what is still open, and each one whose objective has since shipped or been dropped is moved.
- [Permanent work records and the retained-owner transition (2026-09-29)](rules/work-records.md): The Claude coordinator owns all aoe2 work, including Codex's open work items 106–113, until the owner says otherwise. Docs-only publication under `docs/work` runs this repository's `checkoutLineEndings.test.ts` and `workDocsIntegration.test.ts` content checks against the staged files before committing.
- [Several workers in one checkout: disjoint files, and ONE gate run over the combined tree (2026-09-05)](rules/several-workers.md): The rest holds in both modes: no worker runs `npm run verify`; one lane owns the browser pane, the preview port and `dist/`; and every commit checks `git diff --cached --name-only` first.
- [The defect register rolls over, and a live defect never rolls over (2026-09-05)](rules/defect-register.md): `docs/learning/defect-register.md` holds the **12 most recent CLOSED entries plus every OPEN one, whatever its age**, newest first.
- [A batch of commits split from one gated tree: every intermediate state gets the cheap checks (2026-09-06)](rules/batch-split.md): **Run the architecture suite against every intermediate state, not only the last.**
- [The coordinator's operating mode, and the contract every implementer assignment inherits (2026-09-06, owner)](rules/coordinator-mode.md): It has two halves: what the coordinator does and never does, and a standing contract an assignment inherits by writing "the implementer contract applies" and then adding only what is task-specific.
- [A browser spec asserts on frames rendered or on game state, never on ground covered inside a wall-clock window (2026-09-06)](rules/browser-specs.md): No browser spec may require that a quantity move by some amount within a fixed `waitForTimeout`. Hold the input WHILE polling for the state you actually mean and release it in a `finally`; or wait on `waitForRenderedFrames` when the claim is that something did NOT move, because a sleep containing no frames cannot tell "held still" from "never rendered".
- [A coverage floor names a PRODUCER, and a census is compared both ways (2026-09-10)](rules/coverage-floor.md): No self-play gate may put a specific PURCHASE on a floor — a named technology, unit or building type that a match must reach. A floor over a match names the PRODUCER and asks it to produce anything from its own list.
- [Informational visual gallery and DE comparison (2026-10-17, owner)](rules/visual-gallery.md): Maintain an ignored gallery at `tmp/visual-gallery/index.md` in the primary checkout, with dated real screenshots and short captions, and refresh it at meaningful work milestones.
