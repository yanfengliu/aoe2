# A batch of commits split from one gated tree: every intermediate state gets the cheap checks (2026-09-06)

One of [this repo's local rules](../local-rules.md), where "above" and "below" mean earlier and later in its list.

When several commits are split out of ONE tree, the batch is committed first and `npm run verify` runs once, on its top commit, so the gate covers the final state and nothing before it — every commit but the last is unproven. So the cheap per-commit checks run against EACH intermediate state as it is staged. (Amended 2026-10-12, work 124: until then the combined tree was gated before the split, and the split was proven to rebuild it byte for byte. The gate's receipt now names one committed tree, so a tree gated before it is committed earns none, and `node scripts/verify-receipt.mjs check` refuses its landing; gated on the top, the receipt names the tree the push carries.)

**Why:** on 2026-09-06 five commits were split out of one gated tree, and the third would have shipped a defect-register entry standing in BOTH the active file and the archive at once — a rollover half-applied, which is exactly what `tests/architecture/defectRegisterRollover.test.ts` exists to catch. It was caught by the worker reading its own staged set, not by any gate, and the worker's own words are the rule: *no gate would have caught it, because the gate ran on the final state only.* By the final state the duplicate was gone, so a green `npm run verify` was a true statement about the only tree nobody would ever check out. This is not a rollover problem, it is the shape of every batch here: `npm run verify` costs 20-25 minutes, most of it the browser suite, so this repo deliberately gates a batch ONCE (see "Several workers in one checkout" above) and splits it into commits for a readable history — and the readable history it produces is a sequence of states nothing ever checked. Anyone who bisects, reverts, or checks out an intermediate commit lands on one of them.

**How to apply.**

- **Run the architecture suite against every intermediate state, not only the last.** `npx vitest run tests/architecture --reporter=dot` is 1.4 s of wall time for 34 tests across 8 files (measured 2026-09-06), and it holds precisely the invariants a split breaks: the register rollover, thread hygiene, and the file-size budget. The loop is stage by explicit pathspec, run it, read the exit code directly, commit, repeat. It is cheap enough that there is no argument for skipping it; everything more expensive stays where it is, once, on the combined tree.
- **Commit the whole batch, then gate its top.** Run `npm run verify` on the top commit, and `node scripts/verify-receipt.mjs check` before the push. The receipt names the top's tree, which is the tree the push carries, so the old proof that the split rebuilt the gated tree is no longer needed. A hunk that lands in the wrong commit of the batch still leaves the top right, and only the per-commit checks above see the commit it should not be in.
- **Say plainly what this does NOT buy.** An intermediate commit still has not run `npm run verify` — not the browser suite, not the build, not the full unit suite — and it cannot without paying the 20-25 minutes. What this buys is the architecture invariants at every step plus an exact final reconstruction, and nothing beyond that. A bisect that lands inside a batch is still landing on a state whose full gate was never run, so its result is a hypothesis about the batch rather than a fact about that commit. Every commit in the batch still says that the gate covered the batch's top rather than that commit alone, per "Several workers in one checkout" above.
