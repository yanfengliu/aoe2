# Worktrees are the default, and only `scripts/controlWorktree.mjs` makes or removes one (2026-09-22; replaces "A/B control builds: never `ln -s` node_modules into a worktree", 2026-09-05)

One of [this repo's local rules](../local-rules.md), where "above" and "below" mean earlier and later in its list.

Any session or agent doing more than a trivial read works in its own git worktree, per the fleet canon (synced 2026-09-16). On this machine a worktree is made and removed only with `node scripts/controlWorktree.mjs`. `create <name> [<base>]` puts it at `../aoe2-worktrees/<name>` on a new branch `<name>` from `<base>` (default `main`), with `node_modules` as a junction to this checkout's `node_modules`, and prints the path and the branch. `remove <name-or-path>` takes it down and deletes its branch when `main` contains the tip. `delete-branch <branch>` deletes a branch that no worktree holds, on the same condition. `--dry-run` prints the plan for any of them and changes nothing. Nobody runs `git worktree remove`, `rm -rf`, `Remove-Item -Recurse` or `rmdir /s` on a worktree by hand, and nobody puts `node_modules` into one any other way.

**Workers are never spawned with the harness's built-in worktree isolation** (the Agent tool's `isolation: "worktree"`; owner, 2026-09-22). That isolation cleans up any worktree it judges unchanged. A worker killed early by a rate limit leaves exactly such a worktree, because git ignores its `node_modules` junction and the tree reads as unchanged. The cleanup is then a recursive delete through that junction into this checkout's `node_modules`, and through the junctions there into `../civ-engine` and `../voxel`. On the day this rule was written, four of the nine harness worktrees still on disk held that junction. Spawn the worker without isolation; it runs `create` as its first step, or is handed the path `create` printed.

**Why:** on 2026-09-03 `git worktree remove --force` on a control worktree followed a copied `civ-engine` junction and emptied `../civ-engine/.git` down to `refs/` (defect register, 2026-09-05); a 267-character path was all that stopped it. On 2026-09-22 the plain form was measured doing the same thing with git 2.42.0.windows.2, whose lstat calls a junction a directory: `git worktree remove` on a CLEAN worktree whose `node_modules` is a junction exits 0 and deletes the files behind the junction. git's delete of the worktree's admin directory, `.git/worktrees/<id>`, follows a junction the same way. So `--force` was never the hazard; any recursive delete over a junction is. The script removes every link in the tree one at a time with `rmdirSync`/`unlinkSync`, which cannot recurse; scans again and refuses if one is left; refuses if the admin directory holds one; and only then lets git delete. It never deletes recursively itself, passes `--force` only after the plain form failed and a fresh scan is clean, and refuses a worktree whose HEAD is not in `main`, and any uncommitted or staged work unless `--discard-changes` names the loss. `tests/scripts/controlWorktree.test.ts` holds those rules on sandboxed trees, and three mutants show each check sees its defect: cut the unlink step and the fresh scan refuses; cut the fresh scan too and git deletes both canaries through the junctions; cut the admin-directory check and git deletes the canary behind a junction planted there.

**How to apply.**

- **Where.** `../aoe2-worktrees/<name>`, beside this checkout. Not `.claude/worktrees/`: the harness's own tools make and clean worktrees there, and from 2026-07-14 to 2026-09-24 that directory held a `voxel` junction into `../voxel`, made a minute after the harness worktree beside it (23:40 against its 23:39 files), apparently so that worktree's `../voxel` resolved. It was removed with a non-recursive `rmdir` once the voxel build step stopped looking there, and nothing else referred to it. Not `%TEMP%` or a scratchpad: the four scratchpad worktrees found on 2026-09-22 had lost every file to some temp cleaner while keeping every directory, and their paths began about 126 characters deep, close to git's 260-character limit.
- **The harness's other worktree tools.** Do not make a worktree with `EnterWorktree` and a name, and do not remove one with `ExitWorktree` and `remove`: both use the harness's own delete, which nobody here has shown to be safe over a junction. `EnterWorktree` with a `path` may enter a worktree that `create` made, and the harness never removes a worktree entered that way. A subagent pinned at launch can enter only `.claude/worktrees/`, so a worker uses absolute paths instead.
- **Scratch files (2026-10-14).** A worker keeps its scratch files in its own worktree's `tmp/`. The session's scratchpad directory is shared by the coordinator and every subagent it starts, so nobody deletes a file there, or in any shared `tmp/`, that they did not create. On 2026-10-14 a worker cleaning up after its landing emptied the scratchpad with `fs.rmSync` and took four other agents' helpers and logs with it; the listing it printed just before the delete showed files that were not its own.
- **A/B control build of an older commit.** `create <name> <sha>`, build and measure there, then `remove <name>`. The branch goes with it, because `main` contains `<sha>`.
- **Gates inside a worktree.** Every npm script runs in a worktree. From 2026-09-22 to 2026-09-24 the scripts whose first step is `voxel:build` — `test`, `typecheck`, `lint`, `build`, `dev`, and `test:browser` through `build` — exited 127 there, because `scripts/voxel-build-if-stale.mjs` resolved `../voxel` from the working directory; it now finds voxel through `node_modules/voxel`, which in a worktree is the junction `create` makes, and `tests/scripts/voxelBuildIfStale.test.ts` holds that. Who runs the expensive gate does not change: "Several workers in one checkout" below still gives `npm run verify` to one integrator per batch, and a browser suite run from a worktree uses a `PREVIEW_PORT` of its own ("One preview port per session, never the default", below). Never run `npm install` or `npm ci` in a worktree: its `node_modules` is this checkout's.
- **Finishing.** Merge the branch to `main` and push, then `remove <name>` in the same session, as the canon says. `remove` refuses a tip that `main` does not contain and names the branch, and a squash-merged branch is refused the same way. End every task with `git worktree list`: a merged worktree still listed is a defect to report, and one left under `.claude/worktrees/` or a scratchpad is removed by path with the same script.
- **When `remove` refuses, read the reason** rather than reaching for a manual delete. If git's plain remove fails partway, the script stops and says so; what is left held no link at its last scan.

**Owner direction, 2026-09-29 (work reaches main).** The owner asked for the scattered worktree folder to disappear without losing progress, then clarified that everything useful must be on main. Preserving a branch or backup is recovery preparation, not completion. Reconcile every unfinished branch and latest uncommitted overlay, keep useful authored work and evidence with clear provenance, integrate verified results into main, and retire the temporary branches/worktrees in the same session. The sibling `aoe2-worktrees` folder is temporary infrastructure and is removed once its final checkout is retired; no workflow should leave it as a second standing repository. Existing junction-safe controller and final main/worktree audit enforce the retirement boundary.
