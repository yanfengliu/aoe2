# The defect register rolls over, and a live defect never rolls over (2026-09-05)

One of [this repo's local rules](../local-rules.md), where "above" and "below" mean earlier and later in its list.

`docs/learning/defect-register.md` holds the **12 most recent CLOSED entries plus every OPEN one, whatever its age**, newest first. Everything older and closed is in `docs/learning/defect-register-past.md`, moved verbatim. The rollover is done by the task whose new entry pushes the active file past 12 closed, in that task's own commit — never a later sweep, exactly as the devlog archives its detailed file past 500 lines. An entry leaves the active file by being CLOSED, not by ageing: a heading that says the defect is still live is not a closure however it spells it.

**Why:** every other long-lived document here already rolls over — the devlog archives its detailed file, engine-feedback splits `current`/`past`, threads split `current`/`done` — and the register did not, so it reached 1,437 lines and 58 entries before anything split it, while its whole value is that it stays readable. The first rollover then buried THREE live defects, because "(SUPERSEDED … still unfixed)", "(PARTLY FIXED: …)" and "(LATENT, not fixed)" all read as closures to a classifier looking for the word FIXED; they were moved back with `, OPEN` added inside the trailing group and nothing else changed. The rule met its first real use in the same session that wrote it, and the gate caught the rollover being got wrong three times.

**How to apply:** `tests/architecture/defectRegisterRollover.test.ts` is the gate, in `npm test` and so in `npm run verify`. Write every entry heading flush left, exactly `## `, and put the status inside a trailing parenthesised group — `(OPEN` unclosed, `[OPEN]`, `(OPEN).` and a trailing `— OPEN` are invisible to the marker parser and go red as ambiguous rather than passing as closed, which is the direction that would let a live defect roll over. A rollover MOVES an entry and never copies it, and each half's header must name the other. Two consequences of the gate's own bounds, both stated in its header and in `gate-proofs.md`: it does not require the twelve kept entries to be the twelve NEWEST — keeping any twelve closed passes — so **oldest first** is a convention this rule states rather than something the gate enforces; and the oldest closed entry is not always the one to move, because an entry whose marker leaves the defect live (`(PROVEN, fix measured and NOT shipped)` stands in the active file today) is allowed where the reader can see it and goes red the moment it is buried. Move the oldest closed entry the gate will accept.

**Candidate for the fleet canon**, staged here because the defect was paid for here: eleven repos under `github/` keep a `docs/learning/defect-register.md` and this is the only one with an archive beside it (measured 2026-09-05 — `ls ../*/docs/learning/defect-register*.md`, 11 active files, 1 `-past.md`).
