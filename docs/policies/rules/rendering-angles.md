# Rendering is inspected from several angles and zoom levels (2026-08-23, owner)

One of [this repo's local rules](../local-rules.md), where "above" and "below" mean earlier and later in its list.

Whenever the rendering changes, look at the result from **multiple camera angles and multiple zoom levels** before calling it done — not one framing, and not only the region that was edited.

**Why:** the owner asked for it directly, and this repo has paid for it repeatedly: v0.3.34's black-bordered diorama, v0.3.36's tan hill blotches, and v0.3.33's 620px selection panel were all invisible from the framing the author happened to choose and obvious from another one. The fleet canon states the principle ("sweep several camera angles and zoom levels"); this entry is the repo-specific form with the tools named.

**How to apply:** this renderer's isometric angle is FIXED, so "several angles" here means several framings — `scripts/captureMapScreenshot.mjs` takes `SEED`, `LABEL`, `FOCUS="x,y"`, `ZOOM` (camera clamp 0.7-2.4, opens at 2.0), `SIZE="WxH"`, `SELECT="<type>"` (selects the human's first entity of that type — a unit type such as `villager` or `scout`, a building type such as `town-center` or `house`, or a resource in the human's base: `sheep`, `tree`, `berry-bush`, `gold-mine`, `stone-mine` — or `SELECT="box"` for every unit the human owns, the mixed selection a marquee over the base makes; so the command bar is captured in its SELECTED state — where the 2026-09-02 idle-bell overlap lived, and where the bar's height depended on WHICH of these was selected until v0.3.207), `ATTACK="mangonel@24,10"` (selects the human's first unit of that type and gives the right-click order on that cell before the TICKS run, so a shot in the air, where it lands and what its blast leaves can be captured; added 2026-09-26 for the building-centre landing of v0.3.238), `LOAD="<save.json>"` (loads a saved match through the HUD's own Load before the shot, with the page's animation frames held through the load so the capture is of exactly the saved tick on any rasteriser; the only way a late match reaches a capture, since the opening's idle human never grows a base; added 2026-10-15 by work 130, `scripts/captureLoadSave.mjs`), `HOTKEY="F4"` (a comma-separated key sequence pressed before the shot, which is the only way a HUD PANEL reaches a capture — `HOTKEY="F4,Tab,Tab,Enter"` also proves the keyboard path into one, and `HOTKEY="F4,v,i,e,t"` drives a search box), `HOVER='<css selector>'` (rests the real mouse on the first visible match after SELECT, the only way a TOOLTIP reaches a capture — `SELECT=dock HOVER='[data-command="train-fishing-ship"]'` shows the price a command button quotes; added 2026-10-14 by work 125, and it refuses a selector that matches nothing visible), `STYLE="moebius|de"` (the art style to capture under, and the script refuses a frame drawn in any other; sweep a rendering change in BOTH styles, because they differ in kind — Moebius bands tone, so it can hide or exaggerate what the DE style draws as a gradient), `RASTERISER="swiftshader|gpu"` (what draws the frame: SwiftShader, the CPU rasteriser CI draws with and the default, or the graphics card through ANGLE Direct3D 11, Windows only; the script asks the game canvas which renderer drew it and refuses a frame another rasteriser drew, including Chromium's silent fall back to the CPU; look at a shader change on both, because they differ in float precision, derivatives and filtering, and 18.00% of an 800x600 default frame differed between them on 2026-09-24), `GROUND_TIER=blend|single-sample` (which shader draws the Natural ground whatever the rasteriser: unset, SwiftShader gets one surface sample per pixel and a graphics card the blend, so this is how the blend is looked at on SwiftShader; the script refuses a frame drawn in the other tier, and any frame whose Natural ground is not drawn, so pair it with `STYLE=de`) and `PREVIEW_PORT` env vars (which `vite preview` to capture from — with several worktrees on one machine, whatever squats on 4173 is a sibling's build; `npm run test:browser` honours the same variable), so every view in a sweep comes from the maintained script rather than a one-off — capture at minimum a default-zoom view of the real default scenario (`aoe2-prototype`, with fog and a real base: a full-vision showcase fixture hides fog, accent and coordinate defects), a zoomed-in view of the thing that changed, and a zoomed-out view of the whole map. Both scripts write under the gitignored `tmp/captures` (override with `OUT_DIR`), because a capture is task-run evidence rather than a repository input. Pair the before/after of the changed region with `scripts/diffMapScreenshots.mjs` — capture twice as `LABEL=<stem>-before` / `LABEL=<stem>-after`, then diff with `LABEL=<stem>` — per the AGENTS.md visual invariant, and read the diff against this game's ~1% animated noise floor. Give both sides of a pair `TICKS=1` (or the same `TICKS`): the init-script pause freezes the sim but not which frame of the minimap's first reveal the canvas shows, and two DIFFERENT builds freeze on different frames — measured 2026-09-02: ≤4/255 per channel across the minimap, 0.66% of a 1280x720 frame on top of a 0.58% change, while same-build pairs were 0.00% and `TICKS=1` pairs exact — so a "confined to the change" claim needs both frames drawn after the pause. The last look is always a whole-frame sweep for what is WRONG, including parts the change never touched.
