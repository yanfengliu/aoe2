## 3. Alternatives considered before selecting a contract

- **Extend the same default-map run.** This preserves the original scenario and can add comparisons beyond tick 600. The earliest possible full load is at least tick 748 under the inspected state, with actual travel and deposit later. It is valid only if the final test still completes under its existing 30-second limit. No inspected evidence establishes the required end tick or complete cost. Moving the prefix into a hook, pre-warming worlds outside the timed case, or comparing only selected later frames would conceal cost or remove proof and is not accepted.
- **Keep the original 600 and add a real lifecycle on an existing fixture.** This preserves the historical regression population and cleanly adds missing coverage. `woodline-clearing-fixture` is the strongest wood-specific candidate found: it retains the 60x36 terrain dimensions, has both AIs disabled, one owner-2 villager at (9,10), a Town Center at (4,8), and a reachable 12-wood tree at (10,10), with a second tree behind it (`fixtures/economyBasics/woodlineClearing.ts:20-46`; `mapGeneration/constants.ts:16-17`). Existing `tests/simulation/woodlineClearing.test.ts:51-70` expects the near tree to be exhausted by 700 ticks and verifies later delivery after save/load. That is source-grounded support for trying a 700-tick lifecycle bound, not a fresh observed pass. Its single worker removes ambiguous same-owner simultaneous deposits. Owner 2 still auto-maintains gathering with AI disabled by the established rule (`bridge/pureHelpers.ts:326-330`); explicit gather commands in both replay worlds must still be asserted accepted.
- **Use another existing economic fixture.** `ai-economy-fixture` has a 500-tick stockpile-increase check (`createSimulationBridge.gatheringAndDropoff.test.ts:11-54`), but it exercises sheep and AI ownership/multipliers. `fish-fixture` uses a real human command and a 700-step deposit bound (same file:57-87), but it proves food and shoreline behavior. The shepherd-control fixture has one nearby villager and Town Center, but changes the resource to food. These could prove a generic gather/drop-off lifecycle; they do not replace a wood-specific claim without saying so. `resource-depletion-fixture` starts with only one wood and cannot prove a full 10-wood load. Mock drop-off and loaded-villager tests exercise branch decisions, not a complete real-world gather/deposit cycle.
- **Change default rates, cargo, geography or the selected tree; shrink the world; weaken equality.** These are not acceptable repairs to the original case. A distinct fixture is permissible only as an additive, explicitly different proof. No product change is justified by this coverage defect.

**Recommended minimal corrected contract:** retain the original 600-tick default-map test and all 600 native full comparisons, rename it to the bound it actually proves, add tick-advance and selected-worker real-gather witnesses, and add one separate wood lifecycle case using the existing woodline fixture with no fixture edits. Use all fields and native exact comparisons at every stepped tick of the added case too. A fixed 700-tick window is a defensible initial bound from existing tests; its actual passing lifecycle, cost and 30-second limit remain empirical acceptance requirements. If a different window is selected after observation, record that as a new instrument input. Do not weaken the original 600 population.
