# Proposed actual-host contract for transparent compaction — 2026-10-18 UTC

Status: read-only decision preparation, not implementation authorization. Base: aoe2 `63443d0dfe9eaefe900be02b10f0e46e94235dbc`. No browser, build, test, profile or product edit was run for this investigation. Root owns the next decision and shipping-pin proof.

## Read sources and existing bounds

The exact reviewed prototype is `../software-culling-proof-1017/tmp/probes/work130-culling/candidate.ts`, SHA-256 `c56cbf5647f5e8e9e08f6f95496f9243d9edbc9a943a9924fbfaee0faa11e5f5`. Its `prepare(source,camera)` returns the same outer source revision, stamps eligible batch revisions with that outer revision, and stages pending metadata. Only `commitDrawn` with the matching presented epoch/revision and an actual draw promotes it. First/count/resource/layout changes remain full until that draw. Opaque and animated batches bypass compaction; six true conservative extrema and retained instance order preserve the proved bounds/sorting contract. Its 320×200 projection and four-CSS-pixel margin are synthetic bounds, not approved host dimensions or AA/outline bounds.

`AoeVoxelWorldRenderer.ts:244–286` packs ground, builds the adapter snapshot, synchronously admits it, updates ground, checks adapter hit revision against the admitted tuple, then records pending hits. `:307–338` updates the view and draws independently of `present`. `AoeVoxelPresentationCoordinator.ts:169–185` skips presentation when tick, interpolation, interaction and selection are unchanged; camera is absent from that skip key. `AoeVoxelGameView.ts:383–398` still updates camera and calls renderer.frame while paused/halted. Initial base centering happens after deps.present (`Coordinator.ts:210–215`), so the first draw can already use another camera.

`AoeVoxelWorldRendererDelta.test.ts` uses the actual AoE renderer and actual ThreeRenderRuntime with a draw stub, covering deltas/fallback and an outgoing epoch rollback. It does not cover compaction or the real coordinator. `createApp.replayRollback.test.ts` uses the actual app/view/coordinator/adapter and actual RenderWorld validation for rejection and same-size/resized post-admission ground failure, but replaces ThreeRenderRuntime with FakeRuntime. The fake reports frames=0, so it cannot certify actual committed-draw advancement. Neither surface currently proves this integration.

## Recommended smallest route

Prefer internally re-presenting the last successfully accepted projected input through the existing adapter, at the exact same display time, for a camera-only membership change or one required refresh after a full batch commits. Keep coordinator deduplication and bridge ownership unchanged. This retains one epoch/revision domain: adapter source outer revision = admitted wire outer revision = pending/presented hit revision. It avoids inventing revision translation across normal frames, capture, hit readiness and rollback.

Retain an owned successful input tuple: displayed entities, simulationDisplayTimeMs, and all overlay/frame values. It is the already smoothed projected input, not a request to re-read the bridge, re-run the smoother, step simulation or rebuild screen-space overlays from a new camera. Define ownership explicitly: borrowed mutable arrays/objects must not change a retained input after admission. Copy only what lacks a proven immutable producer contract; do not assume a shallow readonly type supplies one. Keep the complete canonical adapter snapshot separate from the last emitted/accepted compacted wire snapshot. All compactor count/resource decisions use canonical source; delta base construction uses the actual last accepted wire snapshot.

`present()` must continue doing synchronous preparation and runtime admission before returning. Deferring acceptance to frame() breaks `replacePresentedBridge.ts:14–27`: its try/catch commits the bridge owner as soon as sync() returns. Ground packing remains before adapter/admission. Retain new cache/compactor pending state only once the complete presentation succeeds, including ground update and hit-identity validation. Do not replace those failures with a queued promise or a later frame error.

In frame(), apply actual viewport/view first, prepare at most one needed cached-input refresh, then call runtime.frame. A camera signature must include viewport width/height, DPR, world/projection matrices and the proven visual-margin policy. Use the actual draw camera. The public runtime already accepts an OrthographicCamera through its constructor; lending that same object is a possible seam without private access. It changes the engine's reported camera ownership and therefore needs a manifest/ownership regression assertion. A separate camera configured by the public camera helper avoids that ownership change but duplicates camera state and needs exact matrix equality against the actual render callback at every tested size/zoom. Do not hand-build a third projection or infer the camera from only viewCorners.

If an ordinary present used the preceding camera, frame must refresh before drawing a camera-dependent compacted plan. An all-full pending plan is camera invariant: it can draw at the current camera without a redundant first admission. Initial auto-centering must not cause an accidental second initial snapshot merely to obtain a camera. Passing the current camera through the real view's present callback can later avoid duplicate preparation while moving, but is not required to establish the first bounded contract.

## One post-full refresh is necessary

The helper's first/count/resource-full rule alone is insufficient on the real paused host. After that full source actually draws, the coordinator can skip forever, leaving the expensive full lane forever. Schedule one cached-input re-presentation after a matching full commit, even if camera and simulation are unchanged. The next preparation sees committed source count/resources and may compact. Its subsequent compacted commit schedules nothing; an idle paused host must then stop ingesting new revisions.

The smallest useful helper seam is explicit preparation metadata describing whether a plan has camera-dependent membership and whether its matching full commit needs one refresh. Do not infer this from equal source/output counts: a normal compacted plan may retain every currently visible slot and still depend on camera, while a mandatory full plan is deliberately camera invariant. Expose a prepared/adopted token or an equivalent bounded pending-plan record so rejected preparation does not replace the last successfully admitted pending plan. This is a local state contract, not a new general transaction framework.

Only a real commit can arm that one refresh: capture metrics.frames immediately before/after runtime.frame, require an increment of exactly one and matching presented epoch/revision, then promote the matching pending plan. frameIndex/framesDrawn attempts are not a commit instrument. Independently observe public runtimeStatus in the real-runtime proof to distinguish lost, restoring and terminal failed states. A lost admission, superseded pending revision or old revision redrawn during restoration must neither promote the new plan nor arm a refresh. Reset eligibility only when a genuinely new runtime/Scene is constructed; a new instance starts with a fresh helper. Ordinary restoration must follow the separately proved restored-previous-frame behavior, not pretend the latest admission was drawn.

## Why not wire-revision remapping first

Reusing a canonical adapter snapshot unchanged for camera-only admissions is cheaper CPU work, but a new wire revision is mandatory. Installed RenderWorld rejects a same-epoch snapshot whose outer revision is not newer (`render-world.ts:438`), and delta puts/patches also require newer item revisions. Changing batch membership while reusing source/outer revisions is invalid.

A wire-counter route must allocate a monotonic wire revision for every admission, including normal simulation sources after camera-only increments; stamp eligible emitted batch revisions with it; retain source↔wire identity for pending and presented hits; compare adapter hits with source before restamping/mapping; keep last wire as the delta base; and update capture/inspection/readiness/rollback semantics. Resetting the counter or using source revision again after a camera pan can regress the accepted revision. It also needs explicit retained-source and pending/presented lifetime rules across context restoration and bridge replacement. This extra identity domain is not required by current evidence. Revisit it only if a measured/contractual problem defeats the simpler route.

The re-presentation route still needs proof: equal-time unit motion returns the prior state when the root did not move (`aoeVoxelUnitAnimation.ts:245`), but that does not prove all poses/overlays/history are idempotent. It can also cause additional adapter work while continuously panning. Those are tests/measurement limits, not grounds to assume equivalence or savings.

## Bridge transaction contract

Begin each new bridge with a fresh compactor and empty cached input/pending refresh state. Keep the previous adapter, canonical input/source, last wire snapshot, pending/presented hits, clock, compactor object and its pending/committed state, camera signature and refresh reason only inside the existing bridge transaction. A fresh compactor forces the new epoch's first batch full. Do not reset the outgoing object in place.

If synchronous preparation/admission fails, restore the outgoing owner/coordinator and those renderer fields. If the incoming wire snapshot was admitted before ground/hit failure, restore the previous accepted wire snapshot as the existing rollback does; restore Natural ground bytes, geometry and texture references via ground.beginUpdate. The previous compacted wire snapshot, not a newly culled source, is the restoration input. A following actual frame can promote only its matching outgoing pending state. Ground packing cache should also be restored or explicitly invalidated; an incoming cache cannot become the authority for camera-only refresh after rollback.

On success, release references to outgoing bridge/cached source/compactor when the transaction closes. Rejected or superseded preparation cannot leak an adopted incoming plan into the outgoing helper. No GPU resources belong in the compactor; reset/disposal follows the actual runtime lifecycle, and terminal failure does not become a usable-frame capacity exception.

## Minimal tests-first actual-host proof proposal

Use a small fixed projected world containing both translucent lanes, many offscreen slots, six extrema, an ordinary visible live unit, a remembered entity and a building. Use the real coordinator, real AoeVoxelWorldRenderer/adapter, public ThreeRenderRuntime and an owned Scene/DrawRecorder; replace only the GPU rasterizer. At each render callback inspect real InstancedMesh count/capacity/order/matrices/colors/bounds and the actual camera. A second unmodified host fed identical projected inputs is the structural oracle. Do not replace adapter.prepare, inject the compactor result directly into runtime or assert only helper watermarks.

| Case | Required actual-host observation / meaningful negative control |
| --- | --- |
| Paused initial/full transition | Coordinator admits once; first actual draw has full canonical counts and presenter capacities. Next unchanged frame performs exactly one fresh outer revision and may compact; ten further unchanged frames admit nothing. Removing the post-full-refresh trigger must fail the compaction/progress assertion. |
| Paused pan and zoom | Keep tick/alpha/selection/interaction identical and show coordinator present count stays unchanged. Drive host frame cameras through membership-changing pan, zoom and size changes; a new wire/source/hit revision appears before the relevant draw. Disabling camera refresh must expose a named omitted visible instance. |
| Clock/input/overlays | Same display time preserves unit/animal/attack/work poses, animation clock and actual hit part matrices; no bridge step or smoother call occurs. Preserve placement/marquee/selection overlays exactly from the cached input. Mutating a producer-owned array after successful admission must not mutate the retained redraw input. |
| First/count/resource full until commit | Coalesce several admissions without drawing; every required plan stays full. Test grow/shrink across capacity buckets and geometry/material/layout replacement. Inspect actual first drawn mesh capacities, not accepted payload length. Omitting first/count/resource-full must fail the corresponding observation. |
| Sparse/fallback/order | Keep exact retained canonical order, six extrema, bounds/sort keys and opaque/animated bytes equal to the unmodified host. Force delta resync/rejection and inspect full fallback plus the next delta's actual wire base. |
| Hits and public identities | Live unit can be hit after the exact admitted revision commits; before a lost/superseded draw it exposes no incoming hit state. Memory/shadows remain non-selectable. InspectPartMatrix/public capture revision must identify the displayed wire/source tuple consistently. |
| Lost/restoring/reconstruction | Independently assert runtimeStatus, device generation, metrics.frames delta and exact presented tuple. Lost draws and an old restoration draw do not commit latest pending state or arm refresh. Genuine new runtime/Scene draws full first, then compacts once. |
| Refused bridge admission | Exercise the real replacePresentedBridge function with real coordinator/renderer/runtime; reject after adapter preparation. Owner/display/cache/clock/old compactor/wire base remain outgoing; retry starts the incoming epoch full. |
| Post-accept ground failure | Reuse same-size and resized Natural ground fault cases with actual ThreeRenderRuntime. Confirm restored ground bytes/references/disposal, old wire/hits/compactor/cached input, then pan while paused and continue a normal delta on the outgoing bridge. Defer only the GPU rasterization assertion. |
| Successful bridge change | First incoming committed draw is full; exactly one later compact refresh occurs. Retained state contains no outgoing bridge/input/helper reference. Cover replay enter/scrub/replace/exit ownership through the existing real-app surface where appropriate. |

This proposed no-GL host proof still does not establish browser controls, real context restoration/GPU resources, actual viewport/DPR/AA/outline pixel conservatism, shipping-pin behavior or Normal performance. Those remain separate approvals/proofs. No test or implementation above has run. A small renderer-local lifecycle helper may be needed to keep AoeVoxelWorldRenderer below the 500-line cap; do not grow the coordinator into a second render owner.
