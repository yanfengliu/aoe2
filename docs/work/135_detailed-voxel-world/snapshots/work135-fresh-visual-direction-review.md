## Fundamental flaws

The wider game image uses conflicting levels of construction: large flat building planes and thick trim, repeated foliage tiers, slab-like ore, block-body people/animals, noisy flat ground and simple water streaks. The University image independently exposes flat walls and roof tiers with little construction-scale detail. This is a whole-world authorship problem; fixing a pine alone cannot bring those neighbors to the requested tier. HUD implementation is outside this review.

The inspected references share deliberate form hierarchy. Teardown separates masonry, timber, terrain, character and light. Town to City makes roofs, openings, braces, planting, paths and shore edges read as a related place. Latica puts tiny repeated elements inside strong terraces, deep cuts and gateways. Voxelnauts reads through pose, anatomical separation and organized bright/dark masses. Merely adding more small cubes or procedural color variation does not supply those decisions. Teardown's cinematic lighting and Latica's huge static construction also have different costs from an RTS; those screenshots are not proof of achievable live-game cost here.

The effort has repeatedly optimized occupancy statistics and evidence machinery before the first convincing Normal image. Accurate matrices, pinned inputs and cleanup make observations trustworthy, but they do not make the artwork good. The critical path is now a deliberately authored original subject that looks substantially better at its real game size. Another broad survey, source-only review cycle or sixth conifer recipe will not answer that question.

## One next milestone, after the UI release

**Author and render one original open-sided timber quarry shelter, using an existing small-building gameplay footprint.** This is one primary subject, not another whole-family revamp. Its reference is Town to City T03's timber market shelter at the front-left of the middle building: approximately45-degree elevated isometric presentation, visible open bay, posts, braces, roof edge and strong timber/roof/ground separation. Teardown informs material/value restraint; Latica informs depth cuts. The design itself remains original. The courtyard family and broadleaf tree are deferred until this subject passes.

Use a fixed palette-indexed volume as the authoring source: literal hand-authored voxel slice maps or coordinates, exposed through the existing public surface mesher. The author explicitly places occupied cells, openings and material regions; no lobe/cone functions, seeded shape synthesis, density fitting or parameter search generates the subject. A simple finite data-to-mesh conversion is sufficient. Do not first build a generic importer or editor. If an available voxel editor is preferred, export one original static model and reduce it to the same audited occupancy data; that tool choice does not change the acceptance. Keep the authored volume as the editable original, rather than preserving only its mesh.

Scope the asset to one roof, four load-bearing posts, visible diagonal braces, a genuinely open working bay, a small stone footing and one workbench. Major form first, construction detail second, restrained palette/variation third. Do not add the worker, ore cluster or tree in this milestone. This prevents an attractive neighboring asset from hiding a weak main subject.

Before authoring, capture the chosen existing building at1600×900,DPR1,Normal1.5 and pin its real projected box, world dimensions and camera. That exact baseline box is the Normal footprint contract; the asset retains the same gameplay/world scale. The proposed roof should occupy approximately the small shelter's140–200px-wide regime, not the several-hundred-pixel close-view regime. This range is a proposed framing check, not a measurement of an existing shelter in the inspected screenshots. If the actual existing footprint differs, root records its measured box before any artwork; no later camera/scale changes may enlarge the candidate to rescue legibility. The first candidate must be judged at that frozen box. Close3.4 is supplementary.

Acceptance order and hard stops:

1. Produce the original occupancy asset and the first actual in-game Normal image, plus one same-subject close image and pinned before/diff. Compare the whole subject to the retained native T03 original. Bay depth, posts/braces, roof thickness and timber/stone separation must read at Normal without explanation. There is one initial first-look verdict before expanding coverage.
2. **Stop this candidate** if it still reads as a flat box with thick trim, if the open bay collapses into a black painted square, if braces/roof structure exist only in the close view, if noise substitutes for construction, if the Normal framing changes, if geometry exceeds the existing role cap, or if an implementation merely renames procedural shape formulas as authored data. Do not extend captures, relax thresholds or initiate automatic parameter repairs after that rejection.
3. If that visible first-look passes independent art judgment, freeze the exact accepted volume/mesh and compare public standalone versus actual game using the same camera, materials, light, tone, fog and shadow inputs. Apply the already demonstrated public mesh-shadow route where supported. Attribute any material visual loss with a matched image pair and named adapter setting or specifically proved missing public feature before requesting engine work.
4. Then inspect additional actual game framings, both styles and surroundings; use maintained before/after/diff tools and confinement. Verify real selection/placement behavior and unchanged footprint/visibility contracts. Record exact mesh/part/batch counts and representative repeated-shelter live cost before full gates, integrated review and shipping.

The first deliverable is a visibly improved original shelter at its real Normal footprint, not a new protocol, source-only packet or third-party showcase. A passed shelter would establish one authored construction grammar and a bounded game/renderer comparison. The whole-world request remains open.
