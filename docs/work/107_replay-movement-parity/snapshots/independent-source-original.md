## Findings

No material source or contract finding. The additive version-1 `aoe2.movePaths` envelope persists the chosen full route, entity generation, original ordered target and resolved destination. It leaves the cursor in runtime state and derives the restored cursor from the unit's current coarse cell. This addresses equal-cost suffix replanning without changing the existing movement solver or deliberately changing pacing. See [codec](C:/Users/38909/Documents/github/aoe2-worktrees/replay-parity-250/src/game/simulation/bridge/bridgeStateSerialize.ts:321), [route type](C:/Users/38909/Documents/github/aoe2-worktrees/replay-parity-250/src/game/simulation/bridge/movePathPersistenceTypes.ts:3) and [hydration](C:/Users/38909/Documents/github/aoe2-worktrees/replay-parity-250/src/game/simulation/bridge/persistedMovePathCache.ts:41).

Compatibility has the required explicit split. [Initialization](C:/Users/38909/Documents/github/aoe2-worktrees/replay-parity-250/src/game/simulation/bridge/persistedMovePathCache.ts:16) preserves an absent historical replay slot, while new worlds and user-loaded old saves enable the slot. The ordinary world factory defaults to live mode, and the replay factory explicitly selects replay mode. Unsupported versions and malformed envelopes reject with an error naming the slot and accepted version/routes shape. Invalid individual rows are removed and left to the ordinary planner; duplicate IDs are rejected rather than silently selecting one supplied route.

[Route validation](C:/Users/38909/Documents/github/aoe2-worktrees/replay-parity-250/src/game/simulation/bridge/persistedMovePathCache.ts:88) requires the current live unit generation and current move/attack-move order, finite integer in-bounds cells, a nonempty cardinal route with no repeated cells, the current coarse cell and the final resolved destination. It uses restored world dimensions. Requested target and reachable fallback remain separate. Hydration copies canonical fields and the runtime route separately; accessor decode/flush also clone their boundary values, so cursor mutation cannot mutate the snapshot or a second loaded world. Publication happens on route set/delete/clear, through the normal accessor dirty flush; advancing the runtime cursor does not itself publish a route write.

The existing planner still checks the next step's passability and refreshes a blocked or obsolete route. The original target-unblocks behavior remains intact.
