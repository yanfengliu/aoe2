# Debugging instruments (aoe2)

What exists for debugging this repo, and the question each answers. This list moved here from the Debugging line of [AGENTS.md](../../AGENTS.md) on 2026-10-29; that line keeps the rule that an existing instrument comes first, before any probe of your own, and that every probe names its instrument.

- What exists, and the question each answers: `bundleHotspots(bundle)` — which ticks are worth looking at (tick failures, execution failures, duration outliers, markers); it is pure and builds no world, so it goes first in a triage.
- `snapshotAtTick(bundle, tick)` — world state at any recorded tick, folded from the nearest snapshot with ZERO World construction and no game code; the cheapest ground truth there is.
- `npm run replay:inspect -- <bundle> --ticks a,b,c` — THIS repo's own script (`scripts/replay-inspect.mjs`), not an engine capability: it wraps `SessionReplayer` with an aoe2 world factory to print aoe2-shaped per-owner rows (record a bundle with `npm run playtest -- --all-ai --max-ticks N`).
- `diffBundles` and `SessionReplayer.forkAt` — two recorded runs compared structurally, which is what an A/B is.
- `SessionReplayer.selfCheck()` — whether the recording is deterministic, asked BEFORE trusting anything read off it.
- `WorldHistoryRecorder` with `summarizeWorldHistoryRange` — records and folds a LIVE world with no bundle at all, so "no bundle exists for this configuration" is not a reason to hand-roll a probe.
- `createVisibilityDebugProbe(key, visibility)` on `WorldDebugger` — takes a `VisibilityMap`, which this repo does build (`simulation/createSimulationBridge.ts:84`), so unlike the two probes below it is type-compatible and will attach; the map is a local in the bridge factory with no accessor on the bridge, so reaching it costs a one-line export, not a redesign.
- `npm run ai:tick-ab -- <scenario> <treeA> <treeB>` answers whether equal simulated work costs more in one tree, interleaving both in one process with digests and foreign load, where `--load <save>` boots both trees from one saved game in the castle or lab configuration, which answers what a tick costs in a world no scenario reaches (a late match, a scratch map), and `--projection on-read|every-tick` puts both on the self-play gates' render projection or the game's, which answers what the projection costs on that world when the two runs are read side by side (work 150 M2); `scripts/profile-selfplay.mjs --config castle|lab` reports self/inclusive CPU shares on the gate's match, with `--players`, `--save` and `--load` for equal-world comparisons.
- `npx tsx scripts/selfplay-ab.mjs --a <tree> --b <tree>` (work 144) answers whether a change to the computer moved its matches or they moved by themselves: it plays several seeds per map (`--seeds 5`; map M's are M, then `M#1`, `M#2`, ..., and the default map's first three are `aoe2-prototype`, `default-seed` and `corpus-seed-b`) in both trees, a process per match and six at a time (`--jobs`), and reports every column of `scripts/selfplay-audit.mjs`, plus the age clicks and the villagers at them and at 5, 10, 15 and 20 minutes, as each arm's median and range and the per-seed difference with how many seeds moved each way. `--b-seed-offset K` plays arm B on other seeds, which measures the noise floor of a median; plan 144 records it. The match is `scripts/selfplayAuditMatch.mjs`, which the audit shares.
- `src/game/playtest/aiEconomyTrace.ts` (work 141) answers how one seat's economy ran: villagers, population against cap, stockpile, what its Town Center was doing, and its Houses. It reads only components and `aoe2.*` slots, from a live world (`liveWorldSource`) or a `snapshotAtTick` snapshot of a recorded bundle (`snapshotSource`). It folds them into housed runs, Town Center idle time by reason, and the House and age timelines. `tests/simulation/aiEconomySelfPlay.test.ts` gates on it.
- `node scripts/dumpDeHotkeys.mjs [GROUP ...]` (work 142) answers which key Definitive Edition binds to a command by default: it reads the install's `hotkeys.json` and string table (never launching DE) and prints each entry's `definitive` key with its modifiers and fields.
- `node scripts/saveFrameRate.mjs --save <save.json> --focus <x,y>` (work 150 M2b) answers what frame rate a loaded save draws and what a frame costs the main thread while it does: the save goes through the HUD's own Load into a production build on a vite preview (`PREVIEW_PORT`, and `--tree` for another checkout's build), and a row holds the frame rate, a frame's cost in its animation-frame callbacks, ticks per second, the runtime's counters per drawn frame, what the world holds, where the camera stood and the machine's busy CPUs. It refuses a preview that is not serving that checkout's current build and a frame another rasteriser drew. `--profile <file>` also records the main thread's CPU profile and prints where its time went by phase (`scripts/framePhases.mjs`), for frames that ran a simulation tick and frames between ticks apart, naming minified code through the build's source map (build with `npm run build -- --sourcemap`); `node scripts/foldFrameProfile.mjs <file> --heaviest 40` folds a recorded profile again and lists its heaviest functions. `--gpu-sync` reports the wait for the GPU after every callback. A profiled row is slower than the game, so frame rates come from rows without `--profile`; alternate the builds being compared and report `busyCpus` with every number. The gates beside it count work per frame, because a frame rate cannot be a CI gate.
- And civ-engine ships a read-only MCP server (`../civ-engine/mcp`, `node mcp/dist/cli.js --corpus <dir>`): 14 tools over a bundle corpus, conversational, constructs no world.
- Two engine probes do NOT serve this repo and no doc should send you to them again: `createOccupancyDebugProbe` takes an `OccupancyGrid`, and this repo holds an `OccupancyBinding` whose grid is `private` with no accessor, so it does not attach — and its payload is eight scalars (a width, a height, a version and five counts), so even attached it counts cells and names no cell and no entity; `createPathQueueDebugProbe` wants a `getStats(): PathRequestQueueStats`, and movement here is synchronous `findGridPath` plus a local cache with no queue anywhere, so it does not apply at all.
- Who is blocking whom is answered by `bridge.getDebugSnapshot()` — `coarseVsFine` carries every unit's cell and sub-cell position and `unitPaths` its current move target — which is what the freeze investigation actually used.
- `bridge.isCellPassableForUnit(unitId, x, y)` (work 152 M1d) answers whether the path search may step a unit onto a cell. It is the search's own predicate, read through the bridge: terrain for the unit's domain, buildings, resources and the map's edge, with a finished gate of the unit's own side admitting it; an id that names no unit reads as a land walker no gate admits. It is no command and nothing a save holds. The search also counts the cell a unit stands on as open, which is the search's rule and not this predicate's. `tests/simulation/cellPassabilityAccessor.test.ts` holds it to the walk the game makes through seven kinds of ground. `staticGridOf` (`src/game/playtest/walkDistanceProbe.ts`) is the independent rebuild from components, and reads a farm, a foundation nobody has started and a seat's own gate as walls.
- `tests/simulation/builderWalkProbe.ts` (work 152 M1d) answers which villager a computer seat sent to a building site, and who else it could have sent: `observeBuilderOrders(bridge)` records every placement and crew order at the instant the seat decides (it wraps `bridge.pendingCommands.push`, and reads only), with the builder's walk, each other available villager's walk, who is the last on a resource and whether the game would refuse the placement; `walkToSite` and `stepsBetween` are its own searches over the accessor's grid; `betterBuilders(order)` names who should have gone instead. `aiEconomySelfPlay.test.ts` and `selfPlayContentCoverage.test.ts` gate on it.
- The rule was skipped twice as prose alone (2026-06-13, 2026-09-05); the tools it named were audited on 2026-09-06 and the asks that came out of that are in `docs/engine-feedback/current.md`.
