# 2026-08-24

## Self-healing units, and the technology that was waiting on them (v0.3.65)

**Timestamp:** 2026-08-24, continuing the same session as v0.3.60–v0.3.64.

**Action:** shipped unit regeneration (the Vikings' Berserk line, 1 HP every 3 seconds) and Berserkergang, the Imperial Castle technology that doubles it. Fixed two pre-existing defects found on the way: a red lint gate on main, and a spec table that had drifted from the code.

**What was believed and proved false.**

*That a technology whose effect is a RATE can keep that effect outside the technology table.* The first version put `BERSERKERGANG_REGEN_MULTIPLIER = 2` in `unitRegeneration.ts` and gave the `UNIQUE_TECHNOLOGIES` entry no effect field at all, with a comment explaining why. `uniqueTechnologies.test.ts`'s "gives every technology an effect of some kind" guard rejected it — correctly, because that guard exists to stop a technology costing 850 food and doing nothing, and it cannot tell "effect lives elsewhere" from "no effect". The fix was to move the number onto the entry as `regenMultiplier: 2` and have `regenPerTick` read the table, so the technology's whole effect is visible in one place and the guard stayed strict. Widening the guard would have been one line and would have blinded it.

*That a passing simulation test means the player can see the effect.* Four simulation tests proved the Berserk healed at the right rate, in a real match, from a real save blob. The browser test — the health bar, read off the render — showed **zero** change across 300 ticks. `step()` opens with `flushOutOfBandRenderChange()`, so the projection refreshes only when a mutation marks it; damage sites call `markRender`, the technology sweeps call `markOutOfBandRenderChange`, and the new system called neither. The state was right and the screen was wrong, which is the exact failure mode a numbers-only test cannot see. Swept the class afterwards: every other `currentHp` writer (projectiles, blast, monk heal, repair, Loom/Sanctity/Bloodlines) already marks.

*That a fight would supply the wound the browser test needed.* The first fixture stood an enemy militia next to the Berserk to wound it. The probe showed the militia at `idle` while it was beaten to death, and the Berserk at 55/55 — `autoAggressionSystem` skips owners with `disableAi: true` by design, so a passive enemy really is passive. `ScenarioSpawnSpec.startHp` exists for exactly this and made the fixture three lines shorter.

**What a check caught that the author missed.**

`npm run lint` had been failing on `main` since e576d00 (the Petard) and 656e2b3 (Hoardings and El Dorado): a prose comment sitting as the only content of a `case` label reads to ESLint as a fall-through. It survived two commits because the gate was being run as `npm run lint 2>&1 | tail -1` and eslint's last line is blank — filtered output that looks exactly like success. Recorded as a lesson (read a gate's exit code, unpiped) and fixed by moving each comment into the body it explains.

Then, while adding the Vikings row to §9.2.2, the table turned out to have 17 rows against 18 implemented technologies: El Dorado has been researchable since v0.3.57 and the spec never learned. The sentence above the table still said "Sixteen of the nineteen". Both halves are now read by `tests/architecture/specUniqueTechnologyTable.test.ts`, which compares the table's `(civilization, technology, age)` rows to `UNIQUE_TECHNOLOGIES`, checks the count sentence, and checks that every deferred id is named in the paragraph below. Red-checked by deleting the El Dorado row.

**What number moved and from what.** Berserk regeneration: 0 → 1 HP per 3 seconds (1/30 per tick), doubled to 2 by Berserkergang — measured on `vikings-regeneration-fixture` as 10.0 → 23.3 → 30.0 → 40.0 HP at ticks 0/100/300/600, which is exactly 1 per 30 ticks. Deferred unique technologies: 2 → 1 (`atheism` alone). Implemented: 17 → 18 of 19. Tests: 2681 → 2692 passing — eight for the mechanic and the technology, three for the spec-table gate.

**Notes for later.** Atheism is the last deferred unique technology and needs three things this build lacks: Wonder and Relic victory timers to change, and a Spies/Treason cost to halve. It is honest where it is until then.
