### Reasoning

The closed replay-scrubber thread §5.7 + §5.6 specified the contract: replay should not let the user mutate state through annotation hotkeys, and the marker list should reflect what's being replayed (not the live recording, which the bridge has paused). Implementing this through optional dependency injection on `MarkerListPanel` keeps live-mode behavior unchanged — pre-Slice-1 tests pass with `replay: undefined`. Pulling the Alt+M gate into a tiny helper file makes the behavior explicit, named, and unit-testable without standing up a full createApp test rig.

The hardening against `JsonValue` marker fields was Codex iter-1's catch and is preventative for the file-import slice (Slice 4) that loads arbitrary user-supplied bundles. The prototype-pollution path was Codex iter-2's catch — a real exploitable bypass through inherited `Object.prototype` properties that `Record<string, string>` truthy lookups can't detect. The `Set.has` swap fixes it categorically because `Set` storage is internal and not consulted via property access.
