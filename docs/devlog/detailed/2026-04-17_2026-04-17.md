## [2026-04-17 13:35, America/Los_Angeles] - Preserve game aspect ratio and make minimap clicks center the camera exactly
**Action:** Letterboxed `#game-root` to a fixed 5:3 aspect ratio in `src/styles.css` so the Phaser canvas never stretches when the viewport shape differs from the 60×36 world. In `src/phaser/scenes/GameScene.ts` and `src/ui/hud/createHudController.ts`, scaled pointer coordinates by `canvas.width / bounds.width` so clicks line up with world cells when CSS size differs from internal canvas size. Switched `centerCameraOnWorldPosition` to `camera.centerOn` (which already applies Phaser's `useBounds` clamp) and rewrote `getCameraScrollBounds` to match Phaser's own `clampX/Y` formula — the old clamp used `[0, world - view]` and bounced the camera away from world edges when zoomed in. Computed the snapshot's `viewX/Y/Width/Height` directly from `scrollX/Y`, `width/height`, and `zoom` rather than reading `camera.worldView` (which is integer-rounded every frame by the `pixelArt: true` path). Added a `pointer.moveTime === 0` guard to `getEdgePanDelta` so edge-pan doesn't activate before the real cursor has ever entered the canvas — Phaser's `activePointer` defaults to `(0, 0)`, which is inside the top-left edge zone. Added a new browser test that zooms in and then clicks the minimap center, asserting the camera lands exactly on the world center; tightened the existing drag/click minimap tests so they assert the exact expected center (with max-scroll clamping) instead of only checking a direction. Rewrote the "viewport shrinks" test to assert letterboxed dimensions.
**Result:** `npx.cmd vitest run` passes with `76` tests, `npx.cmd tsc --noEmit` clean, `npx.cmd vite build` clean, and `npx.cmd playwright test` passes all `57` browser tests (including the new exact-minimap-click centering test). The game canvas preserves pixel-art aspect under any viewport shape, minimap clicks land exactly on the clicked world position, and edge-pan no longer drifts the camera before the user has moved their cursor.
**Files changed:** `src/phaser/scenes/GameScene.ts`, `src/styles.css`, `src/ui/hud/createHudController.ts`, `tests/browser/game.spec.ts`, `docs/learning/lessons.md`, `docs/devlog/detailed/2026-04-17_2026-04-17.md`, `docs/devlog/summary.md`
**Reasoning:** The old `getCameraState` read `camera.worldView`, which Phaser rounds each frame — so exact-position assertions on the minimap were off by up to a pixel. The old `clampCameraToWorld` used a scroll range of `[0, world - view]` that corresponds to the camera TL origin but Phaser's `useBounds` uses a different formula based on `displayWidth`; when zoomed the two disagreed, so the camera couldn't reach the right/bottom world edge via `centerOn`. The CSS fix removes the need for DPR or aspect-ratio workarounds in coordinate math because the canvas now always has the same aspect as the world. The edge-pan guard is a root-cause fix for a pre-existing bug exposed by the sharper test assertions: without a real mouse event, the default `(0, 0)` pointer is indistinguishable from "user hovering top-left", so `pointer.moveTime === 0` is the right "has any real event landed" signal.
**Notes:** The `pixelArt: true` flag in `src/app/bootstrap/createApp.ts` is the reason Phaser rounds `scrollX/Y` and `worldView` — that's still the right setting for this game, we just stopped relying on the rounded output for precise world math.
