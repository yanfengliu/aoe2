# 2026-07-07

## v0.1.116 — Isometric building material breakup

**Timestamp.** 2026-07-07 00:36:55 -07:00

**Action.** Used the new screenshot-backed vision loop on the real default `aoe2-prototype` view and shipped the next AoE2-style graphics polish slice: completed tall isometric buildings now draw subtle base-parallel masonry course lines across both visible wall faces and sparse diagonal roof tile seams inside the roof diamond. The change is pure presentation and localized to the Phaser building renderer; footprints, hit testing, health bars, selection, construction, fog memory, simulation state, saves, and replays are unchanged. Version bumped to 0.1.116 and the changelog/spec/current isometric plan were updated.

**Code reviewer comments.** In-process adversarial review: visual default-view comparison confirmed the original issue was the first-viewport Town Center reading as one large flat tan block, so the implementation should add small material cues without changing game mechanics or the art style. A self-review finding caught that the shared `drawIsoBuilding` path would also add completed-building masonry/roof seams to tall construction stubs (Castle/Wonder), which would make incomplete buildings read as finished; fixed by adding a `materialDetail` style flag and passing `false` from the construction-stub path, with a regression test in `tests/phaser/buildingRenderer.test.ts`. Documentation review grep found a stale current-plan reference to wall banding as future work after the feature shipped; updated the summary and isometric design thread so only per-civ/architecture-set texture variation remains in that slot. Multi-CLI review was not run because this was a low-risk render-only slice with no persistence, security, money, dependency, concurrency, or data-loss blast radius.

**Result.** `isoBuilding.ts` now exposes pure geometry helpers for wall-course and roof-tile segments and draws the material detail only for completed tall buildings. `buildingRenderer.ts` keeps construction stubs visually plain. Focused tests cover the new geometry contracts and the construction-stub exclusion. The visual protocol captured before/after/default-view evidence under `tmp/vision/default-view-before`, `tmp/vision/default-view-after`, and `tmp/vision/default-view-diff`; the canvas diff was 2,719 / 983,040 changed pixels (0.277%), confined to the building area.

**Reasoning.** Real Age of Empires II buildings carry a lot of small wall and roof texture that helps them read as built structures at default zoom. The current procedural art should not chase exact copyrighted assets, but it can borrow the composition lesson: large flat planes need restrained, repeatable material cues. Lines were chosen over new filled shapes so windows, doors, owner tint, roof accents, HP bars, fog, selection, and construction states keep their existing visual priority.

**Validation.** `npx.cmd vitest run tests/phaser/isoBuilding.test.ts` failed before implementation on missing helpers and zero material-detail lines, then passed after implementation. `npx.cmd vitest run tests/phaser/isoBuilding.test.ts tests/phaser/buildingRenderer.test.ts` failed before the construction-stub fix because a castle construction stub produced 11 completed-building line segments, then passed after `materialDetail: false`. Full gates passed: `npm.cmd test` (216 files passed, 1 skipped; 1789 tests passed, 2 skipped), `npm.cmd run typecheck`, `npm.cmd run lint`, and `npm.cmd run build`. Dependency audit was not required because no dependency surface changed.

**Notes.** The LLM playtest harness completed a bounded opening pass before the visual fix (`playtest:llm`, max 250 ticks, screenshot every 250): it accepted 5 commands and left the game in progress, with no game-rule defects identified for this slice. Remaining isometric polish: per-civ/architecture-set facade variation, fuller unit and wildlife figures with attack/death feedback, and elevation/cliffs once the engine exposes the per-cell-elevation render contract.
