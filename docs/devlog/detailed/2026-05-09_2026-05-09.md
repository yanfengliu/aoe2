## 2026-05-09T11:00:00-07:00 - ClaudeCodeProvider for subscription-auth playtest (no API key needed)

### Action

User uses Claude Code on a subscription, not an API key. The LLM-agent-playtest harness was built around `AnthropicProvider` (which requires `ANTHROPIC_API_KEY`), so the runner gated hard on that env var. Added a peer `ClaudeCodeProvider` that shells out to the `claude -p` CLI — auth comes from whatever Claude Code is configured with (subscription via OAuth/keychain). Runner now auto-selects: claude-code if the `claude` binary is on PATH and resolvable to `.exe`, else api if `ANTHROPIC_API_KEY` is set, else fail loud. Explicit `--provider <claude-code|api>` flag overrides detection.

Mid-implementation, split `src/game/playtest/llmProviders.ts` (681 lines) into `src/game/playtest/llmProviders/{mockProvider,anthropicProvider,claudeCodeProvider,index}.ts` (each <500 LOC) per the user's "every code file ideally under 500 lines" rule.

**Provider mechanics:** stream-json input over stdin (multimodal: text + base64 images), stream-json output (parse multi-event stream, pick the `result` event), `--json-schema` for structured output. The model's schema-conforming response lands in the result event's `structured_output` field (already parsed); we synthesize one text block + N tool_use blocks from `{thought, toolCalls[]}`. Cost + tokens come from the same envelope's `total_cost_usd` + `usage` — no cost table needed.

### Result

`ClaudeCodeProvider` end-to-end live: smoke test against the real CLI returned a valid `tool_use` block in ~$0.10 / ~30 seconds. Unit tests: 21 in `claudeCodeProvider.test.ts` + 1 skipped integration test gated by `CC_INTEGRATION_TEST=1`. Full playtest test suite: 129 passed + 1 skipped. Typecheck/lint/build all clean. ### Reasoning

The Anthropic SDK and the `claude` CLI hit the same models with the same multimodal contract — the sole difference is auth (API key vs subscription OAuth) and packaging (npm package vs spawned subprocess). For a solo-developer prototype where the developer already has Claude Code installed, requiring a separate API key was unnecessary friction.

The CLI's `--json-schema` flag plus `--input-format stream-json` cleanly carries the SDK's tool-use contract: we ask for `{thought, toolCalls: [{name, input}]}`, the model responds with that JSON in `structured_output`, and we synthesize the legacy `[text, tool_use, ...]` content array so the agent's existing `parseTacticalResponse` keeps working unchanged. The `LlmProvider` interface stays a real seam; pure agent code is provider-agnostic.

The two reviewer-only-Claude HIGH findings (H2 cwd inheritance, H3 process orphan) were not catchable from prompt-text alone — Claude found them by running live smoke tests against the real CLI from the repo cwd, which only happens when the reviewer has actual file-reading + bash-invocation tools. This is the exact value-add the AGENTS.md "Reviewers MUST read the codebase" rule demands.

## 2026-05-09T12:09:00-07:00 - Phase-6.A quick wins (ESLint rule + schema drift + timestamped corpus)

### Action

Three small deferred items from the LLM-agent thread shipped together as Phase-6.A:

1. **ESLint `no-restricted-imports` rule for `@anthropic-ai/sdk`** (impl-2 M6). `eslint.config.js` gains a `patterns: [{group: ['@anthropic-ai/sdk', '@anthropic-ai/sdk/*']}]` rule blocking static imports from anywhere except the dynamic-import file (`src/game/playtest/llmProviders/anthropicProvider.ts`) and its test. The pattern form (vs the simpler `paths` form) catches subpath imports like `@anthropic-ai/sdk/error` that would otherwise bypass the guard. Negative-tested: introducing a transient `import { APIError } from '@anthropic-ai/sdk/error'` in a non-allowlisted file fires the rule with the expected message.

2. **Schema-drift detection in `buildAgentSnapshot`** (impl-2 M2). `assertEconomyShape(economy)` runs before any read, asserting `units`, `buildings`, `villagers` are `Array.isArray` and `ages`, `playerResources`, `population` are plain records (not `null`, `Array`, `Map`, `Set`). Throws `[agent-snapshot] schema drift detected: EconomyState.X` on first absent/wrong-type field. Catches engine-side renames/removals that would otherwise silently degrade the prompt (or produce a confusing generic `TypeError`). 9 negative tests + 1 positive empty-state test.

3. **Per-invocation timestamped corpus output dir** (impl-2 M6/M7 deferral). `output/corpus-llm/${date}-${HHMMSS}/` instead of `${date}/` — same-day double-runs no longer clobber each other. The per-row `--out=output/playtests-llm/${date}-${hhmmss}-${run.name}` is similarly timestamped (Codex impl-1 MED 4). Retention pruning's stem-grouping logic in `pruneOldRuns()` is unaffected — the timestamp is part of the basename.

### Result

129 LLM-thread tests pass. Bundle still 553.96 kB (slight increase from the schema-drift-guard module-level helper; @anthropic-ai/sdk still absent from `dist/assets/*.js`). Typecheck/lint/build/full-test-suite all clean.

### Code reviewer comments

**impl-1 (Codex):** 4 MEDIUM — subpath-import bypass, missing `villagers` shape check, record-type checks too permissive (would accept Map/array), per-row `--out` clobbers same-day double-runs. All 4 addressed inline.

**impl-1 (Claude):** 2 MEDIUM (overlap with Codex on subpath bypass + missing `villagers`) + 1 informational LOW (same-second corpus-dir collision is acceptable). All addressed.

**impl-2 (Claude):** APPROVE. All four iter-1 MEDIUMs correctly fixed, no new defects, architecture clean, "fixes are nitpick-level from here." Flagged one comment-staleness nit (retention block referencing the pre-fix stem format) which was patched.

### Reasoning

The three items were batched into one thread because they share the same review cost (multi-CLI iter-1 + iter-2) and have no inter-dependencies. Doing them as separate threads would have tripled the review burden without surfacing any cross-cutting issue the unified review missed.

The pattern-rule semantics matter: ESLint's `paths` config exact-matches the import string, so `@anthropic-ai/sdk` doesn't match `@anthropic-ai/sdk/error`. Subpath imports cross-import the SDK internals (not just the subpath module's own code) and would inflate the bundle by the same ~200 KB. Catching them at lint time is the right gate.

The `isPlainRecord` predicate (excludes `Array`, `Map`, `Set`) anticipates a real engine-side drift mode: the engine codecs are Map-backed, and a future refactor that exposes Map directly through `EconomyState.ages` would silently break `Object.keys(...)` reads. The strictness is intentional.
