# 2026-07-13 — continuous 60 Hz voxel motion (v0.2.1)

## Outcome and boundary

AoE now presents live units and moving wildlife continuously from the exact immediately preceding simulation tick. The simulation remains authoritative and still advances on fixed ticks; the renderer owns only disposable prior-position history, interpolation, eased facing, and procedural part poses. Teleports, rewinds, bridge swaps, generation changes, and non-adjacent tick pairs fail closed to the current position rather than blending across unrelated state.

The cross-game boundary remains unchanged. AoE owns unit roles, gait, heading history, body-forward conventions, and projected resource meaning. The sibling `voxel` package gains only a pure testing reporter for reference-scene frame samples; it does not schedule frames or receive game movement state.

## Implementation

- `RenderStore` snapshots exact prior unit and moving-resource positions before every forward simulation tick. A same-tick projection cannot overwrite that history, and a rewind clears it.
- `AoeVoxelPresentationCoordinator` uses the prior projection only when its tick is exactly `current.tick - 1`; missing or stale history snaps safely. Moving fine-grid resources now use the same display interpolation as units.
- `aoeVoxelUnitAnimation.ts` rotates the complete rigid actor through a bounded shortest-arc heading while preserving authored forward axes for humanoids, cavalry, monks, and siege silhouettes. Hit proxies and contact shadows use the same presented root/body transform.
- `renderMetricsCapture.ts` supplies the normal render/HUD path with alive-entity count and existing ECS metrics. AoE's game-specific `getDebugSnapshot()` remains on demand; full `WorldDebugger.capture()` serialization is no longer constructed by the bridge or routine render path.

## Browser evidence

The named reference was Windows, Headless Chrome 150, ANGLE D3D11 on an RTX 4090, 1280x720 viewport, DPR 1, foreground tab, live `aoe2-prototype` scene. After 60 warmup frames, 658 measured frames over 11.0 measured seconds (12.0 seconds including warmup) sustained 59.82 FPS. Browser callback intervals were p50 16.7 ms, p95 16.8 ms, p99 16.8 ms, max 33.3 ms. Full main-thread callback work was p50 3.9 ms, p95 8.2 ms, p99 11.9 ms, max 19.5 ms. The presented scene held 13 draw calls, 10,396 triangles, 371 instances, 12 terrain chunks, and seven instance batches.

A live selected scout was ordered east and then north through a path corner. Across 150 sampled frames, 69 were moving, 70 positions were distinct, and 78 samples had fractional world coordinates. The root's maximum frame step was 0.1867 world units (p95 0.168). Its maximum heading change was 0.230 radians / 13.2 degrees per frame (p95 0.169), and the facing-to-velocity dot product had median 0.914 and p95 0.996. The locomotion weight and gait phase advanced with displayed speed. `output/playwright/60hz-motion/aoe2-voxel-60hz.png` was inspected at original resolution. This was the original interpolation measurement, captured before the follow-up ECS-publication fix below; it is performance/facing evidence, not the final continuity bound.

These measurements establish the named reference scene and environment. They do not guarantee an exact callback cadence on arbitrary hardware, background tabs, high-DPI viewports, or contended operating systems.

# 2026-07-13 — standalone voxel-only world renderer (v0.2.0)

## Outcome and authority

User direction made voxel graphics the only AoE2 graphics path going forward. The application now creates one interactive Three.js canvas through the sibling `voxel` package. There is no renderer selector, compatibility fallback, second world/input canvas, Phaser source tree, Phaser package, or Phaser production chunk. The DOM HUD, minimap, dialogs, annotation UI, and replay timeline remain UI and do not paint the playable world.

Simulation state remains authoritative. The renderer consumes copied projected data and owns disposable camera, presentation, capture, GPU, listener, resize, and animation-frame state only. Terrain remains elevation-zero. Raised entity clicks use a deterministic AoE-owned proxy generated from the same voxel part recipes; raised terrain and a generic engine query remain future work rather than behavior delegated to a hidden renderer.

## Implementation

- Added `AoeVoxelGameView` as the browser host for bridge stepping, one-canvas lifecycle, direct capture, bridge replacement, resize/fullscreen synchronization, and deterministic frame ordering.
- Moved isometric projection, interpolation, view state, entity hit testing, unit/building roles, camera control, pointer normalization, drag selection, and click/context selection into renderer-neutral `src/rendering/` and `src/input/` modules.
- Added `AoeVoxelPresentationCoordinator` to interpolate projected units, inject simulation display time, center the initial base, and publish stable building/health/placement/display diagnostics.
- Added AoE-owned voxel feedback parts for selection rings, conditional health bars, placement markers, death debris, and hit sparks. Fog now shades terrain snapshot tints instead of allocating transparent per-cell overlay instances.
- Added visible four-segment voxel marquee geometry even for empty drag selections, and invalidated presentation immediately for selection changes while the simulation is paused.
- Derived health-bar height from transformed authored parts and added recipe-projected click/context hit regions for raised walls, units, resources, and roofs. A real canvas click on the Town Center tower roof now selects the Town Center even though the ground-plane inverse misses its footprint.
- Made bootstrap transactional: top-level failures render an accessible fatal panel, constructor/setup failures unwind WebGL/canvas/controllers/listeners/HUD/recording resources, and annotation capture failures keep the marker while reporting the missing attachment.
- Visible 15 FPS elapsed time is no longer truncated to 50 ms. The host preserves elapsed time up to a named 250 ms catch-up bound and resets its clock/input state on document visibility changes.
- Deleted `src/phaser/`, renderer-mode parsing, composite Canvas2D capture, painter-only tests/diagnostics, and the `phaser` dependency/manual Vite chunk. Annotation capture reads the direct Three capture.
- Preserved save/load, replay epochs, browser automation, minimap camera state, input semantics, smooth root interpolation, speed-matched gait, context-loss fencing, and idempotent teardown contracts.
