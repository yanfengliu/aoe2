# Devlog — 2026-07-05

## v0.1.112 — Isometric overhaul: building facade windows

**Timestamp:** 2026-07-05

**Action.** Added a row of dark windows to the two visible iso wall faces of every tall-enough building (the first "facade detail" item on the iso NEXT list, after the v0.1.109 doorway). New pure geometry `wallWindowPolys(baseA, baseB, heightPx)` in `isoBuilding.ts` returns `count` window quads (parallelograms that follow the wall plane) along a face's ground edge; `count = clamp(round(edgeLen / 40), 2, 5)` so a wide Castle wall gets more windows than a narrow House. Each window spans the height band [0.55H, 0.72H] — deliberately ABOVE the door band (0..0.55H), so door and windows never overlap — and is half-width 0.06 of the base edge. `drawIsoBuilding` now, inside the existing `heightPx > 22` facade guard, paints the door (as before) then fills the windows for both the left (`corners.left→bottom`) and right (`corners.bottom→right`) faces with a dark tint (`darken(tint, 0.68)`). Hoisted the previously-inline door `lerp` to a shared module-scope helper and added a local `clamp`. Everything stays a deterministic pure function of the projected corners + height (no random/time); no sim/bridge change.

**Result.** Four gates green (typecheck/lint/build 0; full vitest — see below). `isoBuilding.test.ts` grows to 10 tests: a new `wallWindowPolys` block (returns 4-point quads; count scales with wall-edge length; every window sits in the upper wall band `lift ∈ [0.5H, 0.75H]`; every window stays within the face `t ∈ [0,1]`) plus the updated door test (a tall 2×2 now draws 9 filled polygons — ground + 2 walls + door + 2 windows/face + roof; a short building still draws 4, no door/windows). All 157 phaser tests pass. Visually verified via a throwaway Playwright capture on the `building-showcase-fixture`, zoomed on the 4×4 Castle: a clean row of 4 windows on the lit face + 2 on the shadowed face, so the Castle reads as a fortified structure rather than a blank slab.

**Reasoning.** Splitting windows into a pure `wallWindowPolys` (geometry) + a paint loop mirrors the existing `isoBuildingPolys`/`drawIsoBuilding` split — the geometry is unit-testable without a Phaser stage, and the count-scaling + band placement are asserted directly rather than through pixel counts. Keeping windows in a band above the door means the two facade features compose without any overlap-avoidance logic. Deriving the count from the projected edge length (not the footprint cell count) means the helper needs only the two corner points and stays independent of cell/footprint bookkeeping.

**Notes.** Windows are dark openings (no lit-interior glow) to match the doorway's read; a warm-glow variant is a future option. Remaining iso: wall banding/per-civ facade texture, fuller 3/4-view unit figures + attack animation, wildlife species differentiation, death effects, elevation/cliffs (blocked on the per-cell-elevation render contract — the one civ-engine co-evolution point).
