# Devlog — 2026-07-05

## v0.1.114 — Isometric overhaul: lusher layered tree canopies

**Timestamp:** 2026-07-05

**Action.** Trees rendered as a trunk + one flat tinted circle (v0.1.106), so a forest read as the same stamp repeated. `resourceRenderer` now draws a LAYERED crown over the trunk/shadow: two darker shaded lower clumps (rounded bushy base), the main crown at the raw tint, and a lighter sun-lit highlight offset to the upper-left (matching the buildings' upper-left light). A deterministic per-cell size jitter (`treeCanopyJitter(x,y)` ∈ [0.85, 1.15), same hash family as `terrainRenderer.cellNoise` — no random/time) varies each tree so a forest looks natural, not stamped. Added local `darken`/`lighten` channel helpers. Pure per-frame draw; the shadow/trunk/crown-above-centre/tint contract is unchanged so the existing tree test still holds.

**Result.** Four gates green (typecheck/lint/build 0; full vitest — see below). `resourceRenderer.test.ts` +2 (a tree draws ≥3 canopy circles with a darker-than-crown clump AND a lighter-than-crown highlight; two cells yield different canopy radii — the per-cell jitter). Verified on the REAL default view (`aoe2-prototype`, which has a left-side forest) + a tight forest crop: trees read as rounded, lit, varied woodland; no regression to the rest of the frame.

**Reasoning.** Trees are the most prominent natural feature in the default view and were the crudest remaining element (one flat circle). Layering + a consistent light direction + per-cell variation is the cheap procedural recipe for "lush" without sprite assets. Keeping the jitter a pure hash of the cell (not time/random) keeps it replay- and test-safe like the rest of the render layer.

**Notes.** Followed the v0.1.113 lesson — verified on the real default view (with the forest), not a showcase clip. Remaining iso: wall banding/per-civ facade texture, fuller unit figures + attack anim, death effects, elevation (blocked on the per-cell-elevation render contract).

## v0.1.113 — Fix broken iso rendering in a real match (fog + unit HP-bars + oversized roof accents)

**Timestamp:** 2026-07-05

**Action.** The user looked at the ACTUAL default game (`aoe2-prototype`, with fog + a real base) and said "the screen looks weird." A full default-view capture (not the zoomed showcase clips I'd been using) exposed three iso-rendering defects the showcase fixtures had hidden (they boot with full vision — no fog — and isolated buildings):

1. **Fog of war** (`worldLayers.renderFog`) still painted axis-aligned squares (`fillRect(x*cellSize, y*cellSize, …)`) — top-down coords from before the v0.1.103 iso switch — while the fog layer is in the camera's iso space. Result: a large misaligned black blob across the map. Fixed: each masked cell now fills its iso diamond (`worldToIso` of the four corners), the same tiling the terrain uses, so the shroud lines up. Unexplored = near-opaque; explored-but-not-visible = a lighter shroud.
2. **Unit health bars** (`worldLayers.renderEntityHealthBars`) computed `px = entity.x*cellSize` (top-down) for the layout — v0.1.110 only fixed the BUILDING branch and wrongly assumed units were already iso. Fixed: the caller now passes the iso anchor `worldToIso(x+0.5, y+0.5) − cellSize/2`, matching how the render loop places the unit body, so bars sit on their units.
3. **Roof accents ballooned on large footprints** — `roofMetrics` scaled every accent by the roof diamond's pixel width (256px for a 4×4), so a Town Center turret rose as a ~102px FLAT `fillRect` billboard and a Barracks banner as a ~154px flagpole, both taller than the building. Fixed: capped the accent size reference at 100px (`ACCENT_MAX_SCALE`, also applied to the merlon block height) so a decorative feature stays decorative regardless of footprint; and rewrote `drawTurret` as a small iso box (lit + shadowed wall faces + a top diamond) instead of a flat vertical rectangle.

**Result.** Four gates green (typecheck/lint/build 0; full vitest — see below). New tests: `worldLayers.test.ts` +3 (fog paints iso diamonds not `fillRect`; a masked cell projects to its `worldToIso` corners; a unit bar centres on the unit iso centre, not `x*cellSize`); new `buildingRoofAccents.test.ts` (turret is iso `fillPoints` not a billboard `fillRect`; centre-anchored accents rise ≤68px on a 4×4; a 4×4 accent is no larger than a 3×3 — the cap, not linear scaling). Verified holistically with a full default-view + building-showcase capture: the black blob is gone (fog follows the diamonds), the TC turret is a small tower, the Barracks banner is a modest flag. Ground-truthed the building HP-bar via `getEntityHealthBarStates()` — `entityTopPx=192` sits ~18px above the TC roof's top corner (`worldToIso(8,8).y − 54.4 = 201.6`), i.e. correct; the earlier "floating" read was a wide bar over the diamond's point vertex, not an actual gap.

**Reasoning.** All three are the SAME class of bug — top-down coordinates / width-linear scaling that the v0.1.103 iso coordinate switch left behind and that the full-vision showcase fixtures could never surface. The fix converts each to the iso space the rest of the render layer already uses. Capping accent size (rather than retuning each factor) fixes every accent at once and is a single, testable invariant.

**Reviewer comments.** In-process visual verification only (no multi-CLI pass — presentational render fix, no logic/persistence/security surface). The regression guard is the new spy tests.

**Notes.** PROCESS LESSON (user, this session): "actually visually check your work always." Zoomed showcase captures validated individual features but hid the fog + bar + accent-scale bugs because showcase fixtures have no fog and isolated buildings. From now on, graphics increments verify the REAL default view (`aoe2-prototype`, with fog) at default zoom BEFORE any zoomed feature clip. Recorded in `docs/learning/lessons.md` + memory.

**Timestamp:** 2026-07-05

**Action.** Added a row of dark windows to the two visible iso wall faces of every tall-enough building (the first "facade detail" item on the iso NEXT list, after the v0.1.109 doorway). New pure geometry `wallWindowPolys(baseA, baseB, heightPx)` in `isoBuilding.ts` returns `count` window quads (parallelograms that follow the wall plane) along a face's ground edge; `count = clamp(round(edgeLen / 40), 2, 5)` so a wide Castle wall gets more windows than a narrow House. Each window spans the height band [0.55H, 0.72H] — deliberately ABOVE the door band (0..0.55H), so door and windows never overlap — and is half-width 0.06 of the base edge. `drawIsoBuilding` now, inside the existing `heightPx > 22` facade guard, paints the door (as before) then fills the windows for both the left (`corners.left→bottom`) and right (`corners.bottom→right`) faces with a dark tint (`darken(tint, 0.68)`). Hoisted the previously-inline door `lerp` to a shared module-scope helper and added a local `clamp`. Everything stays a deterministic pure function of the projected corners + height (no random/time); no sim/bridge change.

**Result.** Four gates green (typecheck/lint/build 0; full vitest — see below). `isoBuilding.test.ts` grows to 10 tests: a new `wallWindowPolys` block (returns 4-point quads; count scales with wall-edge length; every window sits in the upper wall band `lift ∈ [0.5H, 0.75H]`; every window stays within the face `t ∈ [0,1]`) plus the updated door test (a tall 2×2 now draws 9 filled polygons — ground + 2 walls + door + 2 windows/face + roof; a short building still draws 4, no door/windows). All 157 phaser tests pass. Visually verified via a throwaway Playwright capture on the `building-showcase-fixture`, zoomed on the 4×4 Castle: a clean row of 4 windows on the lit face + 2 on the shadowed face, so the Castle reads as a fortified structure rather than a blank slab.

**Reasoning.** Splitting windows into a pure `wallWindowPolys` (geometry) + a paint loop mirrors the existing `isoBuildingPolys`/`drawIsoBuilding` split — the geometry is unit-testable without a Phaser stage, and the count-scaling + band placement are asserted directly rather than through pixel counts. Keeping windows in a band above the door means the two facade features compose without any overlap-avoidance logic. Deriving the count from the projected edge length (not the footprint cell count) means the helper needs only the two corner points and stays independent of cell/footprint bookkeeping.

**Notes.** Windows are dark openings (no lit-interior glow) to match the doorway's read; a warm-glow variant is a future option. Remaining iso: wall banding/per-civ facade texture, fuller 3/4-view unit figures + attack animation, wildlife species differentiation, death effects, elevation/cliffs (blocked on the per-cell-elevation render contract — the one civ-engine co-evolution point).
