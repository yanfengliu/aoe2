## 2026-06-16 — M7 "terrain texturing": kind-to-kind blended transitions (v0.1.43) [thread terrain-blending]

- **Action (M7, `[render]`):** softened the hard rectangular seam between adjacent terrain cells of DIFFERENT kinds (grass/forest/water/hill) — the single biggest remaining tile-grid tell after the v0.1.30 per-cell jitter. For each terrain cell, for each of its 4 von-Neumann edges whose neighbour cell is a different kind, the renderer now stipples a deterministic FEATHER band of small specks (Phaser `fillRect`) on the INNER side of that edge, tinted with `blendTint` (the per-channel average of the two kinds' base tints) at partial alpha. The neighbour cell feathers back the same way, so the two stipple bands interlock across the boundary and it reads as a soft, dithered transition rather than a straight line. Pure per-frame (no random/time — every speck derives only from cell coords + edge index via a salted integer hash). 100% original procedural Phaser drawing — no sprites/assets.
- **Investigation (design-aware feasibility, BEFORE coding — the brief demanded I not assume the slice is feasible):** (1) `src/phaser/scenes/gameScene/terrainRenderer.ts` (v0.1.30) draws each terrain cell as a flat jittered `fillRect` + 1px overdraw; called per-entity from `GameScene.renderState`'s flat `state.entities` loop (`if (entity.layer === 'terrain') drawTerrainCell(...)`). Its existing test was `tests/phaser/terrainTexture.test.ts` (NOT `terrainRenderer.test.ts` as the brief guessed) — 6 property tests on `terrainCellTint`. (2) **Terrain data model render-side:** `ProjectedEntityView.entityType` IS the `TerrainKind` for a terrain tile — the RenderAdapter projection (`visibility.ts:projectEntity`) sets `entityType = terrain.kind` (grass/forest/water/hill). Terrain tiles cover the FULL grid (`scenarioSeedOps.seedTerrain` adds one renderable per `scenario.terrain` cell) and are NOT fog-filtered (`renderStateOps` only fog-filters building/resource). So the renderer ALREADY iterates a complete per-cell kind set inside `state.entities` — neighbour kinds are available with no contract change. (3) **ELEVATION:** `TerrainComponent` carries `elevation: number`, BUT `ProjectedEntityView` has NO elevation field — elevation is never projected. Adding it would be a projection/CONTRACT change (forbidden here) → **elevation shading is OUT OF SCOPE for this slice; did the blended-transitions half only** (recorded as a deferral in spec/roadmap/changelog). (4) Base tints from `seedTerrain`: grass `0x587f4e`, forest `0x2f5e34`, water `0x295a75`, hill `0x8c7d5a`. (5) **Before look:** the showcase capture showed every grass/forest/water/hill boundary as a sharp straight rectangular line — the classic tell.
- **The neighbour-lookup challenge + solution:** the scene loop iterates a flat `entities[]` one at a time with no neighbour map. Solution: a WeakMap-memoized `Map<packedXY, TerrainKind>` built from the terrain entities (`terrainKindGrid(entities)`), keyed on the `entities` array reference.
