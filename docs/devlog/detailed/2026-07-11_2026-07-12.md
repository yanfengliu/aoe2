# 2026-07-11 to 2026-07-12

## Isometric voxel renderer — reusable engine plus reversible AoE2 proving slice (v0.1.147)

**User direction.** Build reusable voxel/graphics infrastructure for AoE2, City, and Townscaper; research mature libraries before writing custom infrastructure; co-edit AoE2 only after preserving any existing uncommitted or unpushed work; and leave a durable design/implementation record. AoE2 preflight was clean and exactly `0/0` with `origin/main` at `23f99b7`, so there was no prior work to wrap up.

**Build-versus-adopt decision.** The sibling `voxel` repository now owns bounded renderer contracts, copied typed-array ingest, world/epoch/revision presentation state, a deterministic visible-face correctness oracle, Three.js resource presenters, 2:1 orthographic camera helpers, capture, metrics, context recovery, and disposal. It adopts Three.js `0.185.1` rather than rebuilding a renderer. Voxelize and `block-mesh-rs` are the measured bake-off candidates before any production greedy mesher; Taichi.js stays out of the browser runtime, while native Taichi/OpenVDB remain optional offline authoring tools. City is expected to prove one rigid instance batch; Townscaper first aligns Three versions, then publishes its own irregular shells through geometry resources. The engine implementation and long-lived research/design/plan are committed locally as `7fbae42`.

**AoE2 slice.** Added exact Three/types plus `voxel: file:../voxel`, Vite deduplication, and fresh sibling builds before development and every gate. `.github/voxel-commit` pins the exact shared source, and all three workflows fetch/build it before AoE's `npm ci`. `src/rendering/voxel/aoeVoxelAdapter.ts` maps projected terrain to 16x16 palette chunks and maps deterministic AoE-owned block recipes to a geometry resource plus one rigid instance batch. `AoeVoxelWorldRenderer` owns the Three canvas/runtime, explicit capture, metrics, camera sync, bridge epochs, and idempotent teardown. No AoE type or role entered the shared package.

**Composition and compatibility.** Phaser remains the default. `?renderer=voxel` selects a Three world canvas beneath a transparent Phaser Canvas overlay, preserving the established camera, input, selection, placement, fog, health, transient feedback, minimap, DOM HUD, save/load, and replay seams. Invalid renderer values fall back to Phaser, and Three initialization failure is caught and warned. The adapter intentionally flattens projected elevation because the current overlay/input hit geometry is ground-plane based; raised voxel geometry would otherwise disagree with clicks. Elevation-aware interaction and removal of hidden legacy draw work are explicit promotion backlog, not silently accepted parity.

**Correctness hardening from adversarial review.** Renderer resource versions now namespace world and epoch, so replay or bridge replacement at revision one cannot reuse stale Three resources. Presentation acknowledgement requires the full world/epoch/revision identity and occurs only after a successful render. Instance batches rebind when geometry/material object identity changes even if the batch revision does not. Snapshot validation rejects detached/shared buffers, overlapping chunks, pathological dense allocation/coordinate ranges, geometry positions outside bounds, and overlapping or primitive-splitting material groups. The Three backend rejects unsupported snapshots before accepted state mutates. The AoE path retained separate hit/death feedback layers when legacy entity paint is hidden, uses explicit readback rather than a preserved drawing buffer, and exposes a browser constructor-identity probe.

**Deterministic browser harness hardening.** The larger production bundle exposed six existing browser tests that depended on incidental Phaser frames between a command and `advanceTicks()`. The test API now records pause intent on the final installed API object and temporarily unpauses only around an explicit synchronous step batch. The affected flows boot paused and advance deliberately. The investigation also found that the Skirmisher fixture spawned its enemy Archer inside the player's Archery Range, where it was removed and its id reused before training completed; the old headless test could therefore pass without a real fight. The Archer now starts at `(18, 7)`, outside Town Center arrow range but on the trained Skirmisher's eventual visibility boundary. Both headless and browser tests wait for real projection, issue a real attack, and require the Archer's later removal. The fine-subgrid browser test now uses the same known-clear explicit move route as the canonical simulation test.

**Browser evidence.** `tests/browser/voxel-renderer.spec.ts` proves two correctly stacked canvases; non-empty Three contribution to the composite; `preserveDrawingBuffer:false`; bounded renderer metrics; one browser Three identity; bridge epoch replacement; replay scrub pixel change across a revision-one epoch; real `WEBGL_lose_context` loss/restoration with presentation catch-up; a populated minimap; and the safe Phaser default with no Three canvas. The first full-page voxel capture caught Chromium before its separate minimap canvas layer was composited even though the canvas already contained 10,773 non-background pixels. The final capture waits for minimap pixels and forces that layer to paint; this was a capture-readiness issue, not a runtime minimap defect.
