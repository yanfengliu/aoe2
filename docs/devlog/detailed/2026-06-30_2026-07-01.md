## 2026-07-01 — Drop-off reroute: villagers no longer freeze the economy on an unreachable drop-off (v0.1.55, thread dropoff-reroute)

**Action.** Started the user's marathon `/goal`: run the LLM-playtest→find→improve loop toward a full game, co-evolving aoe2+civ-engine, with meta-attention on whether the harness/loop actually reaches the intended game phases. First move was to ground the premise "the built-in AI reaches the mid-game" against a REAL 8000-tick deterministic playtest instead of trusting it — which OVERTURNED the premise and surfaced a functional bug.

**Find (replay ground-truth, per the debugging rule).** Replayed the 8000-tick default-seed bundle (`SessionReplayer.openAt` + `getEconomyState`): (a) the deterministic run is AI(owner 2) vs an INERT owner 1 (the human slot gets no AI headless), not AI-vs-AI; (b) the lone AI never left the Dark Age — food frozen at exactly 121 from tick 1000→8000, villagers pinned at 6, gold climbing unused to 1270; (c) NO oracle flagged this (a Dark-Age-forever match passed the corpus with 0 HIGH). A per-100-tick food trace showed the two food villagers gathering to a full carry (10), switching to `to-dropoff`, and latching there FOREVER — never depositing. Buildings probe: owner 2 had TWO food drop-offs (TC @(48,24) + Mill @(45,23)) and abundant reachable berries/boars, so it was not a no-farms/depletion problem.

**Root cause.** `villagerEconomySystem` to-dropoff branch called `findNearestDropOffBuilding` (nearest by Manhattan distance, NO reachability check); when the nearest drop-off's approach cells were all blocked (the AI packed buildings around its own TC), `findBuildingApproachPlan` returned null, the loop `setStuck` and retried the SAME unreachable nearest every interval — never falling through to the farther REACHABLE drop-off. The exact symmetric twin of the campaign-11 gather deadlock fixed in v0.1.47, which made the to-RESOURCE leg reachability-aware but left the to-DROPOFF leg latching.

**Fix (aoe2-only; no civ-engine change; no save-format change).** Mirror v0.1.47 on the drop-off leg: (1) `findNearestDropOffBuilding` gains optional `excludeIds?: ReadonlySet<number>` (omitted on the hot path → byte-identical); (2) NEW pure `villagerDropOffAssignment.ts` `findReachableDropOff` probes drop-offs nearest-first, skipping null-approach-plan ones, returns the first REACHABLE `{buildingId, plan}`, bounded by `MAX_DROPOFF_PROBES=8` (common case short-circuits at 1 probe = pre-fix cost). villagerEconomySystem 477→498, targetFindingOps 497→500 (both ≤500).

**Design refinement (surgical — hot path byte-identical).** The FIRST version called `findReachableDropOff` on EVERY non-backoff to-dropoff tick, which changed behaviour on TRANSIENT drop-off blocking (villagers momentarily blocking each other's TC approach) and broke 28 deterministic tests. Reworked so the reroute is a RECOVERY path only: try the nearest by distance first (unchanged); reroute to the nearest reachable alternative ONLY when the nearest is unreachable AND the villager has already been stuck a full `GATHER_DROPOFF_RETRY_INTERVAL` on it (`!dropOffPlan && stuckSince !== undefined` → persistent boxing, not a transient block). Hot path + transient-blocking behaviour byte-identical → all 28 shifts reverted. Cost: a persistently-boxed villager waits ~30 ticks per deposit cycle before rerouting — a small hit in the pathological self-boxing case only (real cure: the AI not self-boxing, a separate follow-up).

**TDD.** New fixture `dropoff-unreachable-reroute-fixture` (a 2×2 Mill sealed by a 12-tree ring = nearest but unreachable food drop-off; a reachable TC farther out; a reachable berry cluster) + `tests/simulation/villagerDropOffReroute.test.ts`. Red: food frozen at 200 (villagers fill carry, never deposit — `expected 200 to be greater than 200`). Green after the fix (food rises ≥ one carry load).

**Validation (playtest re-run — the gap closed).** Re-ran the 8000-tick AI-vs-AI grounding with the surgical fix. Owner 2 food now FLOWS: 141 (t2000) → 466 (t4000) → 626 (t8000), and it AGES UP to Feudal by ~tick 6000 (vs Dark-Age-forever / food-frozen-at-121 pre-fix), villagers 6→7, buildings 6→8.
