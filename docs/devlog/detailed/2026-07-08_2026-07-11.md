### Full-review M4 (save drops in-flight human commands) — CONFIRMED but blocked on a civ-engine API; deferred + reported

**Disposition.** An Explore-agent investigation CONFIRMED the bug: human commands submit straight to civ-engine's TRANSIENT `commandQueue` (a plain array, not `world.state`, not serialized), while the AI's go through the bridge-side, Tier-3-persisted `pendingCommands`. Both vetted fixes are **civ-engine-blocked**, and aoe2 policy forbids modifying `civ-engine`: **Fix A** (route human commands through the persisted `pendingCommands`, as the AI does) needs a PUBLIC synchronous validate-without-submit to keep the accept/reject toasts the HUD shows — but `world.validateCommand` is PRIVATE and `submitWithResult` both validates AND queues (so it can't be used without double-queuing). **Fix B** (drain/process the engine queue in `flushBeforeSerialize`) needs a public `processCommands`/queue-drain — but both are `protected` on `World`; the only public way to process is a full `world.step()`, which would advance a tick at save time (unacceptable). The one in-repo alternative — a shadow-mirror of unprocessed human submissions persisted on save — is unvetted, HIGH-risk (touches the ~10 hot human-input facades + the step loop + save/load + recording timing), and disproportionate to a narrow, low-consequence (one dropped command, no crash/corruption) bug. Recorded in `docs/engine-feedback/current.md` (ask for a public command-validate OR queue-peek/drain API); deferred to a dedicated focused effort with the multi-CLI review rather than rushed in this pass. No aoe2 code change.

### Full-review H5 (movePathCache replay divergence) — CONFIRMED but blocked on a civ-engine fix; reported

**Disposition.** An Explore-agent verification (the finding was flagged "verify first") CONFIRMED a real but NARROW determinism divergence: `movePathCache` is bridge-side/transient (not Tier-1, never rehydrated), and it is BEHAVIORAL not a pure memo — a cache HIT follows the route A* committed from the move's ORIGIN, while a cache MISS recomputes A* from the unit's CURRENT cell, and civ-engine's A* has no position-stable tie-break, so among equal-cost shortest paths the two can pick DIFFERENT intermediate cells (proven by explicit trace: (0,0)→(2,2) standing on (0,1) gives committed next cell (1,1) vs fresh recompute (0,2)). `SessionReplayer.openAt` re-sims from the nearest 1000-tick snapshot with an EMPTY cache, so a unit mid-non-straight-move across a snapshot boundary follows a possibly-different equal-cost route in the replay/`replay-inspect` view than the live run did — a transient, same-destination, intermediate-cell-only drift that `selfCheck` structurally misses (it compares serialized state at boundaries, which excludes the bridge-side cache, and a route that re-converges before the next boundary leaves identical state). **The correct root fix is a position-stable A* secondary tie-break in `civ-engine/src/pathfinding.ts`** (makes the cache provably pure → fixes replay AND save/load with NO save-format change). aoe2's AGENTS.md forbids modifying `civ-engine` directly, and the aoe2-side mitigations are partial + risky (a codec = save-format change; a snapshot-boundary cache reset is replay-only, doesn't fix save/load, and couples the sim to the recorder cadence). So per the "missing engine feature blocks the task → report it, don't modify civ-engine" rule, H5 is recorded in `docs/engine-feedback/current.md` and deferred to an engine fix. No aoe2 code change.
