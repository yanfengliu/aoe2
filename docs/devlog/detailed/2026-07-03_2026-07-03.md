# Devlog — 2026-07-03

## v0.1.80 — Line-of-sight technologies (Town Watch / Town Patrol / Tracking)

**Timestamp:** 2026-07-03

**Action.** Shipped the next loop increment after the v0.1.79 economy fix: three AoE2 line-of-sight upgrades on a new derived-plus-imperative vision seam. Town Watch (Town Center, Feudal, 75 food, +4 building LoS), Town Patrol (Town Center, Castle, 300 food + 200 gold, requires Town Watch, +4 more — stacks to +8), Tracking (Barracks, Feudal, 75 food, +2 infantry LoS). Scouted as the next improve during the v0.1.79 corpus close-out: `visionSource.radius` is a mutable in-place component (the unit-upgrade path at `technologyOps.ts` already mutates it on line 115), so the roadmap's old "building-mutation seam blocker" note was stale for LoS.

**Design (mirrors the Loom/Bloodlines/economy-tech seam).**
- Pure derived helpers — `src/game/simulation/visionTechEffects.ts`: `buildingVisionBonus(researchedSet)` (+4 Town Watch, +4 Town Patrol, stacking) and `unitVisionBonus(researchedSet, unitType)` (+2 for infantry with Tracking, 0 otherwise). Single-sourced constants.
- Imperative bump on research completion — `src/game/simulation/bridge/losTechEffect.ts`: `applyBuildingVisionDelta` / `applyInfantryVisionDelta` add the delta to every owned entity's `visionSource.radius` in place. Wired into three new `applyTechnology` cases in `technologyOps.ts`. The visibility system fingerprints `(playerId, x, y, radius)` per tick, so a changed radius re-stamps the fog on the next tick with no extra dirty-marking — exactly like the existing unit-upgrade vision mutation. `applyTechnology`'s already-researched idempotency guard prevents a double bump.
- Derived-at-creation for future entities — `finalizeBuildingConstruction.ts` (a building finished after Town Watch gets the bonus baked into its base radius) and `productionQueueSystem.ts` (a trained unit gets `unitVisionRadius + unitVisionBonus`). No path bumps the same entity twice: the imperative bump runs once at research completion; entities created afterward take the creation path only.
- Options — `src/game/simulation/bridge/losTechOptions.ts` (extracted to keep `optionsRules.ts` ≤ 500 LOC, matching the economy/tower/monastery tech-options precedent). Town Patrol is gated on `hasTechnology('town-watch')` so it only appears once Town Watch is done; visible-but-locked from Castle Age.
- Cost/time tables, `RESEARCHES_BY_BUILDING` hosting rows, the `ResearchableTechnologyType` union, and the HUD display-name switch all extended. The Research-button command icon is the existing generic scroll glyph (per-tech art is a later slice).

**No save-format change.** The bumped radius lives in the already-persisted `visionSource` ECS component; replay re-applies the research commands deterministically from tick 0.

**AI coupling (deliberately conservative to protect the v0.1.79 age-up timing).** Tracking is a Barracks tech, so the AI's generic research loop (gated behind `!savingForAgeUp`) researches it from a spare Barracks — no age-up regression. Town Watch / Town Patrol are Town Center techs; the AI's TC research block only ever pushes the age-up (it already leaves Wheelbarrow/Loom to the player), so it never enqueues a building-LoS tech onto the TC queue — the exact queue-starvation failure mode fixed in v0.1.79 stays fixed. Building-LoS techs are player-driven for now.

**TDD.** `tests/simulation/losTechs.test.ts` (10 tests, all green): cost/time table values; pure `buildingVisionBonus`/`unitVisionBonus` (stacking, infantry-only, villager/archer/cavalry excluded); offer gating (Dark-Age TC withholds; Town Patrol prereq chain; Barracks offers Tracking); and two live-fog integration tests that research through a real cycle on the new `los-techs-fixture` and assert the Town Center reveal grows 7→11→15 and a standing Militia's reveal grows 3→5 by probing exact `visibleCells` (Euclidean `dx²+dy² ≤ r²`).
