## 2026-06-09 — LLM playtest verification run on ClaudeCodeProvider (no API key): harness works end-to-end, agent is structurally id-blind

- **Timestamp:** 2026-06-09
- **Action:** First real-conditions verification of the LLM-agent playtest on the subscription path: `npm run playtest:llm -- --max-ticks 2000 --observation --out output/playtests-llm/verify-cc` with `ANTHROPIC_API_KEY` confirmed unset and no `--provider` flag, so auto-detection itself was under test. Plus two fail-loud probes: `--provider api` without a key → clean exit 2 naming the env var, before any build; unknown `--bogus-flag` → exit 2 naming the flag.
- **Result — harness plumbing PASSES end-to-end:** auto-detect chose claude-code; 8 tactical Sonnet calls + strategy Opus calls + observation oracle all round-tripped through `claude -p` with schema-conforming output; cost tracking landed at $1.4302 total (~$0.13/decision blended, matching the impl-1 estimate); trace JSONL streamed per decision; envelope written with seed/maxTicks/visualOracle/observation; winner field correctly OMITTED on engineHalt per the Phase-6.D contract; observation oracle verdict `looked-broken` ($0.1355) with an accurate diagnosis ("stuck in a loop of invalid commands rather than playing").
- **Finding A (blocker for the harness's purpose) — agent has zero agency: all 42 commands across 8 decisions rejected** (`not_a_building` ×37, `not_a_unit` ×5; 0 accepted). Root cause CONFIRMED at design level: the tactical prompt (`src/game/playtest/llmPromptBuilder.ts:55-62`) renders perPlayer aggregates, Selection, Enemies, Queued production, and camera bboxes — but never the agent's OWN units/buildings with their `entityId`s. At decision 0 selection is empty, enemies are fog-hidden, queued production is empty → the model sees zero real entity ids for the whole run while the codegen'd tool schemas require integer ids ≥ 1, so it fabricates them (decision-4 thought: "TC is assumed ID 2 for player 2"). `buildAgentSnapshot` itself also has no own-entities-with-ids section (own state appears only as aggregates + queuedProduction buildingIds, which need a non-empty queue to exist). Never caught pre-ship because unit tests use MockProvider with synthetic commands and the real-call integration test is gated behind `CC_INTEGRATION_TEST=1`.
- **Finding B — real-time drift voids tick semantics + visual oracle:** the browser game self-ticks while the agent thinks (~60-100s per claude-code call), so the bridge tick raced to 5413+ while the runner's advanced-tick counter (what `--max-ticks` bounds) read 2000. Baseline checkpoints can therefore never land exactly → all 5 checkpoints skipped → `visualOracle.missingTicks=[1000..5000]`, oracle inert under claude-code latency. Candidate fix: pause the sim during decisions (`bridge.setPaused` exists) or align advances to bridge tick.
- **Finding C — recorder-bundle export broken under Playwright 1.59.1:** `apiRequestContext.fetch: Protocol "blob:" not supported. Expected "http:"` — the Blob-URL round-trip (built to dodge the ~1MB JSON-RPC cap) fails for the 62.5 MB bundle; escalated to `stopReason=engineHalt`, bundle file is a 154-byte stub.
- **Finding D — misleading diagnostic:** checkpoint-skip warns "decisionIntervalTicks=250 doesn't divide 1000" — 250 divides 1000; the actual cause is drift landing the advance past the checkpoint.
- **Finding E — rejection feedback doesn't reach the agent:** the observation oracle's trace summary counts the 42 rejections, but the per-decision tactical context evidently doesn't surface them — the agent re-queued Feudal research at decisions 1-4 reasoning "age hasn't advanced, so retrying" instead of reacting to `not_a_building`.
- **Code reviewer comments:** n/a — verification run, no code changed. Findings A-E are the next thread's backlog; A is the gating one.
- **Reasoning:** the user's ask was "use claude code without an api key to see if llm can actually playtest the game." Answer: the infrastructure can (subscription auth, agent loop, oracles, envelope, cost ceiling all verified live); the agent itself cannot act until the prompt exposes own-entity ids.
