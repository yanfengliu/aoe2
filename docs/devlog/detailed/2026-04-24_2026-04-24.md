# 2026-04-24

## Default-map narrow-path bug: starting villagers walled in by resource clusters

**Timestamp:** 2026-04-24 (continuing through late morning)

**Action:** Fixed a default-map pathfinding bug where the starting villagers
at (6, 8), (6, 9), and (7, 9) on seed `aoe2-prototype` could be completely
walled into a pocket by the procedural resource-cluster placer. The berry
arc at (5, 7)(6, 6)(7, 5)(8, 5)(9, 5) plus the sheep cluster at
(5, 8)(5, 9)(6, 10) and the west-side water/forest strip sealed the
villagers off from the western half of the map. `findGridPath` correctly
returned null for any move target in the unreachable region; the move
command was silently cleared; the user saw villagers that "seemed stuck."

The fix reserves four guaranteed-clear cardinal exit corridors through
the resource-placement predicate in
`src/game/simulation/mapGeneration/applyStandardPlayerOpening.ts` — a
2-row horizontal corridor aligned with the villager spawn rows
(`y = TC.y` and `y = TC.y + 1`) and a 2-column vertical corridor aligned
with the TC center (`x = TC.x + 1` and `x = TC.x + 2`), each extending
13 cells past the TC center (past the outermost forest ring 12). The
`placeResourceCluster` walker skips corridor cells, so no cluster arc can
wrap all the way around the TC and meet an adjacent cluster to form an
impassable wall.

**Reasoning:** `civ-engine`'s grid pathfinder and `OccupancyBinding` both
behave as documented: units stay out of the `blockedBy` list (they only
crowd, per the design lesson at `docs/learning/lessons.md:29-31`), so
narrow corridors populated by friendlies are correctly passable. The
synthetic-corridor regression confirmed that. The only scenario that
actually failed was the procedural default map's specific seed where the
cluster placer wrapped resources all the way around the TC. A
corridor-reservation rule in the placement predicate is the minimum
change that fixes it: it does not touch the cluster-walk logic itself
(still places each cluster's count by ring expansion), does not require
post-generation rework of placed resources, and does not remove any
resources — it only forbids a small cross-shaped band from holding
resources so the ring walker is forced to leave a walkable gap.
