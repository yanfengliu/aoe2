## Rerun finding delta evidence

**Timestamp.** 2026-07-08 02:20:00 -07:00.

**Action.** Added standardized finding-delta evidence to self-improvement rerun comparisons. `src/game/playtest/selfImprovementFindingComparison.ts` compares baseline/current `ImprovementFinding` identities and reports `resolved`, `persisted`, and `introduced` lists. Generic findings use their ids as identities; oracle findings use stable oracle/tick/message evidence identities so generated id suffix churn does not overstate resolved or introduced work. `SelfImprovementComparison` now carries those deltas beside the existing `civ-engine.compareMetricsResults` metrics comparison, and Markdown summaries include a concise finding-delta line.

**Code reviewer comments.** Iteration-4 in-process review found one real issue: raw id comparison was too weak for deterministic oracle findings because `oracleImprovementFindings.ts` includes a positional suffix in generated ids, so the same oracle/tick/message could be misclassified as resolved plus introduced when ordering changed. Fixed by comparing oracle findings through stable oracle/tick/message identity while still reporting the actual finding ids in each bucket. External Codex/Claude review was not rerun for this low-risk internal slice; the prior Codex escalation was rejected for private diff export and Claude remains unavailable on PATH.

**Result.** The loop can now say what happened to specific findings across a rerun instead of only comparing aggregate `findingsCount`.

**Reasoning.** Aggregate count deltas are useful but weak evidence for fix closure: one finding can disappear while another appears. Tracking finding identities makes before/after behavior explicit and lets later fix loops prove whether a target was actually resolved, persisted, or replaced by new work.
