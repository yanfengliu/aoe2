### Fixed

- **H9-bypass — sensitive-path guard was completely bypassable (Codex HIGH-1 + Claude MEDIUM; CONFIRMED by Claude's live git-apply repro).** `applyAndGate.ts`'s hand-rolled diff-path parser diverged from what `git apply` actually writes, via two vectors: (1) **CRLF headers** — a trailing `\r` left every `$`-anchored `SENSITIVE_PATH_PATTERN` unmatched, so `patchTouchesSensitivePaths` returned `[]` for EVERY path and a malicious `postinstall` on `package.json` applied unseen; (2) **case-insensitive FS** — the case-sensitive regexes missed `Vite.config.ts`/`Package.json`, which `git apply` writes to the real lowercase files on the loop's Windows/macOS checkout. FIX: patterns made case-insensitive (`/i`); `patchTouchedPaths` strips the trailing CR (line-level + per-path) and the `\t`-timestamp and normalizes `./`. TDD: 3 new tests reproduce both vectors + the end-to-end rejection (red→green). The residual quoted-path vector is documented as non-exploitable for the plain-named sensitive set (git only c-quotes special-char paths).
- **H6-collision — the within-run finding union over-collapsed distinct conformance findings (Codex MEDIUM-7 + Claude LOW).** The union reused the cross-run `findingIdentityKey`, which deliberately coarsens conformance findings to `[category, area]` for resolved/introduced stability; within one run that collapsed two genuinely-different same-subsystem defects into one (a later HIGH could vanish behind an earlier LOW). FIX: new `withinRunUnionKey` keys conformance findings on their per-finding id (the same defect from markers+envelope shares an id and still collapses; two distinct defects have distinct id suffixes and are both kept); oracle findings keep the violation tuple. TDD: new test keeps two distinct same-`[category, area]` findings while the existing same-defect-both-sources collapse still holds.
- **B — candidate selection ignored verification status (Codex HIGH-3; verifier CONFIRMED, pre-existing).** `selectLedgerFixCandidate` filtered only `classification.kind === 'fix'`, never `verificationStatus`. A finding from a run whose replay self-check FAILED (downgraded to `unverified`, still `kind:'fix'`) could be selected, patched, and — being spurious — vanish on a healthy rerun → `fixed-proven`. FIX: require `verificationStatus === 'verified'` (the union is `unverified|verified|falsePositive|fixed|regressed`; oracle findings default `verified` and only downgrade on replay failure, so legitimate selection is unaffected). TDD: a HIGH `unverified` finding no longer outranks a MEDIUM `verified` one; a lone `unverified` fix yields null.
- **A — a degenerate initial run was reported as a clean `no-fix-candidate` pass (Codex HIGH-2; verifier CONFIRMED, regression-enabled by M6-#5).** After the M6-#5 exclusion of `match-completes` from selection, an initial run that died on `costBudget`/`providerError`/`engineHalt` with no other oracle produced no candidate and exited 0 as a healthy nothing-to-fix pass, appending a clean row to `passes.jsonl`. The rerun side already gates verify+horizon (M6-#6); the initial run did not. FIX: `qualifyInitialRun(ledger)` (verify + horizon, mirroring the rerun gate) → a non-qualifying initial run finishes `initial-run-unqualified` (exit 1), not a clean pass.
- **C — LLM-runner tick accounting + terminal-match mislabel (Codex MEDIUM-6, "→HIGH once matches terminate"; verifier CONFIRMED).** `ticksRun += ticksToAdvance` credited the REQUESTED count, not the observed delta; and with no `getMatchState` check, a COMPLETED match (the bridge's `step` no-ops once `outcome !== 'running'`) presented like a frozen page and the M6-#2 halt check mislabeled it `engineHalt` (winner dropped, match-completes fires, prove-reruns rejected). FIX: added `getMatchOutcome()` to the host; the runner now checks it (`!== 'running'` → `stopWhen`, a genuine horizon) BEFORE the halt check, and credits the observed `tickAfter - tickBefore` delta. The correct pattern was cribbed from the sibling `runPlaytest.ts`. TDD: a mid-run match completion → `stopWhen` (not `engineHalt`) with observed `ticksRun`.
- **fileSizeBudget RED — a self-inflicted regression this review caught (Codex MEDIUM-8; CONFIRMED).** The M14a addition pushed `tests/simulation/saveLoad.test.ts` to 519 LOC (> 500 hard cap), unexempted → the committed file-size gate was RED on main. (The M14 commit's suite actually reported `1 failed`; a stale concurrent task's green summary was misread.) FIX: extracted the shared `captureSnapshot` helper to `saveBlobTestUtils.ts` (519 → 476; util 188 → 234, both < 500). This is the headline value of running the independent review.
