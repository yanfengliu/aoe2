The mechanism below was adjusted by iteration-1 findings: the cover test samples the unit's MID-BODY (visualTop × 0.55, so ankle-high geometry — farm soil/markers, foundation slabs, knee courses — that merely paints at the feet can never fire the cue) and occluder parts require real horizontal mass (min(width, depth) ≥ 0.15 wu, excluding hairline accents like the 0.072 wu TC flag pole whose 2.3 px corridor flashed full-body ghosts on open ground). ## Problem

Units that walk behind buildings become completely invisible in the voxel-only renderer. The former Phaser renderer shipped a white unit-through-building silhouette in v0.1.133 (`occlusionSilhouettes.ts`, commit 14c8321); v0.2.0 removed the whole Phaser path and the cue with it. `design/spec-final.md` §14.5 records the gap twice (the "Voxel feedback supersession" paragraph and the "units behind buildings (voxel follow-up)" bullet). User activated the follow-up on 2026-07-14: "Unit outline should be visible behind buildings."

## Live repro (2026-07-14, default view, real base, fog on)

Dev scenario `aoe2-prototype`, player-1 Town Center footprint (8..11, 8..11). Villager id 2205 ordered from (6,8) to (7,7) — the cell diagonally behind the TC mass from the fixed iso camera. After arrival (sim (7,7), presented root (7.25, 7.75), unit present in `getDisplayedEntities`, i.e. NOT fog-hidden): a 90x120 device-px sample centred on `worldToScreen(7,7)` contains 0 near-white, 0 team-blue, 0 skin-tone pixels of 10,800. The unit contributes zero visible pixels and no cue exists.

## Requirements (from spec §14.5 + v0.1.133 precedent)

1. Any unit (own or enemy) that is visible per the human player's current fog perspective AND whose drawn body is occluded by a non-memory building's drawn geometry shows a readable white silhouette cue at default zoom. Buildings only as occluders (v0.1.133 parity and the user's ask); trees/resources are out of scope this slice.
2. Depth-aware against presented voxel state: the predicate must derive from the same recipes/transforms that actually paint, so cue and paint cannot drift (the v0.1.133 hip-ridge lesson).
3. Fog: a fog-hidden unit gets no cue; memory ghosts neither receive nor cause cues.
4. Determinism: pure function of presented entities + presented time; frozen under pause; replay-safe; no authoritative sim/save/replay/hit-test change.
5. No engine modification required or taken; batch count stays at the pinned 7 (`voxel-renderer.spec.ts` asserts `instanceBatches: 7`).
6. Perf: bounded per-frame CPU — building silhouette regions computed once per frame, AABB pre-reject before point-in-polygon; no per-pixel host work.

## Mechanism (RESOLVED): host-only overlay silhouette — the v0.1.133 architecture transplanted onto the voxel overlay funnel

Decision inputs. Voxel engine audit: `MaterialResourceV1` exposes only shading/color/opacity/transparent/doubleSided/roughness/metalness (`voxel/src/core` contracts.ts:159-169; materialPresenter.ts:19-44); no depthFunc/depthWrite/renderOrder/stencil anywhere; single render pass (ThreeRenderRuntime.ts:797-800); per-instance colors opaque-only (capabilities.ts:60-64). So a GPU occluded-only pass (depthFunc=Greater mirror batch) would need a new engine feature, engine-first publishing, and would double the animated-slot budget consumption for units. aoe2 pipeline audit: every primitive the Phaser implementation used already exists voxel-side, plus a sanctioned way to draw over buildings.

- Predicate (new pure module `src/rendering/voxel/aoeVoxelOcclusionSilhouettes.ts`): a displayed unit (kind unit, not memory) is occluded iff some non-memory building whose MAX footprint-corner depth key (`(x+w-1)+(y+h-1)`; strictly greater than the unit's `x+y`) has a projected silhouette region covering the unit's screen anchor `worldToIso(x+0.5, y+0.5, 0)` — verified to be exactly the unit recipe root (aoeVoxelUnitRecipes.ts:184-185). Max-corner depth (not origin depth, which v0.1.133 used) is required in real 3D: on a building's high-(x+y) flank, deeper wall cells genuinely paint over a unit whose depth exceeds the building's ORIGIN depth; polygon containment geometrically excludes behind-buildings (their base edge projects above a fronted unit's ground anchor), so the pair (max-depth gate + containment) matches painted truth without false positives. Regions come from the same rigid-part recipe projections picking already trusts (`voxelPartIsoPolygon`, static — buildings ship zero animated parts, so no clock threading; aoeVoxelGeometry.ts:156-165), with the hit proxy's shadow/memory part filter (aoeVoxelHitProxy.ts:59-61). AABB pre-reject then point-in-convex-polygon, building regions built once per pass.
- Cue (concatenated in the adapter's part assembly next to `createAoeVoxelOverlayParts`, aoeVoxelAdapter.ts:184-192, states retained via the `updateHitFeedback` precedent): for each occluded unit, mirror its non-shadow recipe parts as `surface: 'ui'` (unlit) parts tinted white — the parts are ALREADY fully posed host-side each snapshot (orientation/gait/attack baked into plain fields, aoeVoxelUnitAnimation.ts:418-487), so mirroring copies the posed fields verbatim, strips any `animation` (the ui lane is force-static; only the ≤1px engine-side ambient wave is lost — accepted), assigns fresh `ui:occlusion:<identity>:<suffix>` keys (duplicate-key guard), and applies the marquee's camera-ray displacement ADDITIVELY (`centerY += 8`, `centerX/Z += 8·V/H ≈ 9.798`, aoeVoxelOverlayParts.ts:129-134 constants; NOT the marquee's absolute y=lift) so silhouettes depth-test in front of any building ≤8 wu tall (tallest existing: TC flag 3.24 wu — 2.5× margin, near/far planes fixed at 0.1/4000 with camera distance 1000, so no clipping). Do NOT route mirrors through `makePart` (it would memory-gray the tint). `VoxelOverlayEntity` gains `readonly parts` (runtime objects already carry them; type-only widening, no other constructors exist). Reusing `ui` keeps the static batch set unchanged → 7 batches (requirement 5); worst-case instance count is ~2 orders below the 200k/batch ceiling and the animated-slot budget is untouched. Per-instance colors are opaque-only at the engine boundary, so the cue is a solid white silhouette (AoE2-HD-style), not an alpha ghost — accepted.
- Fog correctness is inherited, not re-implemented: the renderer only ever receives the bridge's fog-filtered entity set (`isCurrentlyVisible`, renderStateOps.ts:56-67), and `makePart` forces memory surface for ghosts (aoeVoxelRecipeTypes.ts:153-157) while the predicate excludes `isMemory` on both sides (requirement 3).
- Test seam: `getOccludedUnitStates(): OccludedUnitState[]` restored along the historical 4-hop chain (viewTypes → coordinator/renderer state → `AoeVoxelGameView` passthrough → `browserTestApi`), mirroring `getBuildingVisualStates`. `AoeVoxelGameView.ts` is at 450/500 LOC — passthrough only; all logic lives in the new module.
- Determinism/pause: the snapshot rebuild is change-gated (tick/alpha/interaction/selection, AoeVoxelPresentationCoordinator.ts:168-174) and the animation clock advances only with forward simulation display time — under pause nothing rebuilds and the presented frame freezes byte-identically (grep-verified: zero Date.now/Math.random/performance.now in src/rendering). Inputs are displayed entities only ⇒ replay renders identically through the same funnel (requirement 4).

## Why not the engine depthFunc route (recorded for the future)

Pixel-exact partial x-ray (only the hidden fragment glows) is strictly prettier but costs: a game-neutral engine contract addition (depth compare + render order through MaterialResourceV1/parseMaterial/materialPresenter + per-batch renderOrder), engine-first release ceremony, doubled animated-slot budget for mirrored unit batches (aoe2 budgets against MAX_ACTIVE_INSTANCE_ANIMATIONS_V1 = 8192), and draw-order subtleties vs the transparent memory-ghost lane. The overlay route ships the user-visible cue now with zero engine risk; if a later slice wants per-pixel x-ray, the engine extension path is documented here and in the voxel capability report.
