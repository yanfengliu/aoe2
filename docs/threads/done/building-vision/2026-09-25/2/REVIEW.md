## Findings and dispositions

- **R2-1 HIGH — every replay recorded before this change would fail to open.** civ-engine's replayer refuses a world whose state-key count or component entry counts differ from the snapshot it was built from (`factory_snapshot_not_applied`). A replay world added the building slot, and the load-time repair added a vision source to every old House. Confirmed by a test through the engine's own replayer before the fix: `BundleIntegrityError`, "world-state key count (20) does not match the construction snapshot (19)". Fixed: a replay world writes the building slot only when its snapshot has one, as the attack-feed slot already did, and the repair runs for a loaded save only. Gate: `tests/replay/buildingSightLegacyReplay.test.ts`, red under M25 and M26. The docs that said old recordings load as before now say what happens: they open, and re-simulate with the new sight.
- **R2-2 MED — a world rebuilt from a snapshot or a save stored a different `aoe2.buildingVisibility` than the live world at the same tick.** The slot keeps the ground only buildings explored, computed when it was written, and it was written only when a building's sight changed; as units explored, the live slot went stale while a rebuilt world computed it fresh. Play was unaffected, but a replay's self-check and a save-load-save round trip compare this state. Confirmed by a probe before the fix: at the boot map's tick 1,000, 42 and 77 cells live against 22 and 17 loaded. Fixed: the slot is kept current at every tick, computed whole after a building change and otherwise as the last answer less the cells units have explored since (exact, because until a building changes the building layer's cells stay put and the units' explored cells only grow), and written only when it differs from what the world holds. A live, a loaded and a replay world then hold the same value at every tick; the probe that found the defect reads equal at all six of its checkpoints. Gate: `buildingVisibilitySlot.test.ts` "holds what the map holds now, at every tick, in a live world and in one loaded from its save", which compares the live slot with the map's own answer (asked of a replay world built from the live snapshot) and a loaded world with the live one, at the load and 50 ticks later. It was red on the code before the fix, and M17, M22 and M31 turn it or its neighbours red. The reviewer's alternative, the building layer's whole explored set with nothing subtracted, is simpler and was not taken, because the engine walks every slot twice a tick and that set is the larger part of what the first slot cost.
- **R2-3 LOW — round 1's post-load owner test loaded a state no real save can produce, so the leak a save can carry was ungated; and no test removed a building source with the cell lists cached.** A save holds no building source, but it can hold a unit's under the owner it had before a conversion no sync saw. Fixed: the case is now that unit, loaded through the real two-slot path (M27 red), and the cache case removes the building's sources (M28 red).
- **R2-4 LOW — recordings no longer describe building sight, and the debug probe AGENTS.md recommends mixes the layers.** Neither slot holds a building source, so a snapshot-only reader sees no building sight, and `createVisibilityDebugProbe` rows count one layer's sources and explored cells but both layers' visible cells. Fixed in docs: ARCHITECTURE and decisions say what a recorded snapshot holds and how to rebuild building sight from components, AGENTS.md says how the probe's rows read, and the line it cites (`createSimulationBridge.ts:84`, now 85-87) is corrected there and in the probe hook.
- **R2-5 LOW — the building slot sorted every building source only to drop them.** Fixed: the map tracks its building-layer players and reads each one's explored cells, which the engine returns in index order, only after a building change; between changes it only drops cells from its last answer.
- **R2-6 LOW — the docs claimed more than the code.** "Holds only the cells no unit explored" is now true at every tick (R2-2). The cost is now one figure everywhere: about +0.27 ms/tick in the engine's two state walks together, on the boot map's tick-30,000 world. The round-1 record's T9 line named ARCHITECTURE among the documents citing both foundation references, and it cites neither; its P5 line said an older build's buildings "see as that build's did", when every finished building there would see from its top-left cell; both lines are corrected. The Teuton "+1 attack" comments in the two files this change touches are corrected; the older one in `entityCreateOps.ts` is left. "Answers every query from both layers" now names what does: the four sight questions and `clearPlayer`; `getSources` and `removeSource` act on the layer the id names.
- **R2-7 NIT — API hazards with no caller.** `clearPlayer` on an owner now clears both layers (M29 red). `createWorld` now takes only the layered map, so a plain engine map no longer type-checks there. Left, with no caller depending on either: `getMetrics` counts a units-layer miss twice, and the returned cell lists share their `Position` objects with the map's cache.
